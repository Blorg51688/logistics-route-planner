# 项目速懂（图版）

> 一眼看懂整个项目怎么跑。**深度内容不在这里**——完整版（备查，含追问答法）见
> [`项目速懂-详解.md`](../../docs/项目速懂-详解.md)。想看门面与常用命令 → 根目录 `README.md`；全部文档地图 → [`docs/文档导航.md`](../../docs/文档导航.md)。

**一句话**：城市物流网络建成**有向带权图**（30 节点 / 106 有向边 / 25 订单），用手写二叉堆 + Dijkstra 预计算全源最短路，
再用**penalty 先的 pair-insertion** 把每张订单的**取货 A→送达 B** 串成**一条连续路线**；配送过程由**软件内时间**驱动四类事件，事件可触发**顺序不变版重放的增量重规划**。

## ① 一张图：数据怎么流

```text
config/default.ini            ← 30 节点 / 106 有向边 / 25 订单，三车 V01 400kg·1.00·1.50 / V02·V03 160kg·1.25·0.80
   │  IniFile::parse（手写解析，带行号报错；退役键在此拦下）
   ▼
ConfigLoader::load  →  Config{ graph, vehicles(6 列), orders(7 列), general(事件等级) }
   │
   ▼
RoutePlanner::planRoute       ← 单条连续路线（基地 → 紧急段 → 普通段 → 基地）
   │      ├─ CostMatrix：V×V×3 全源最短路（一次建表，之后 O(1) 查 leg）
   │      ├─ 紧急段：订单级 FIFO 尾插
   │      ├─ 普通段：EDD 序 + pair-insertion（失败 → repair R≤3 → 全量兜底 → 降载）
   │      └─ 取优：字典序 (Σpenalty, 策略权重, tieKey)
   ▼
RoutePlan
   ├─ stops[]          ← **真源**（每次停靠带动作集：取/送/降载/取回 + 阶段 + 时刻）
   ├─ offloads[]       ← 降载 custody（同车卸、同车取）
   ├─ metrics          ← S / A / 逐单 penalty / 两率 / 平均在车 / 峰值
   └─ nodes/stops 视图 ← 由 finalize() 一处展平，不各自维护
   │
   ▼
GUI 推进：onAdvanceStop / onAdvanceMoment（逐节点，不许跳站）
   │
   ├─ 移动前/后必调 settleEventsUpTo(now)   ← 事件结算挂在"软件时间前进"上
   │      └─ SimEvent::nextEventTimeMin（每 15 分钟一个刻）+ pickEvent（等级派生 27:3:9:1）
   │
   ▼ 四类事件
   ├─ 路况    Traffic::simulateTrafficChange → needsReplan？→ replanIncremental（顺序不变版重放）
   ├─ 紧急单  RoutePlanner::insertOrder（FIFO 尾插）
   ├─ 普通单  RoutePlanner::insertOrder（pair-insertion）
   └─ 封路    GraphEdit::closeRandomRoad（不封桥）
   │
   ▼
syncScene()  →  路径高亮 / 拥堵标记 / 车辆位置重绘
```

**手动动作**（不在事件池里）：插入紧急订单（A/B/kg 表单，前缀 U）、模拟新客户（建节点 + 普通单，前缀 C）、手工增删。
**旁路**（不走 GUI、不需显示器）：`--dump-graph`、`--plan-summary`、`--dump-plan`、`--self-check-actions`、`--ui-probe`、`--render-window`。

## ② 一张图：路况怎么触发重规划

```text
软件内时间前进（推进一站 或 推进一刻）
        │
        ▼
  过了事件刻？──否──▶ 无事发生
        │是
        ▼
  pickEvent 抽一个（路况 : 紧急单 : 普通单 : 封路 = 27 : 3 : 9 : 1）
        │
        ▼ 抽到路况
  simulateTrafficChange：round(0.1 × 106) = 11 条边
     畅通 → timeMin 恢复 baseTimeMin      （增幅 0，不触发）
     拥堵 → timeMin = baseTimeMin ×(1+20%~50%)   ← baseTimeMin 永不改，是判定基准
        │
        ▼
  needsReplan：这条边在**当前路线的相邻两站之间**且增幅 ≥ 20% ？
        │                                    │否
        │是                                  └──▶ 不重算
        ▼
  replanIncremental：**停靠顺序完全不变**，把剩余停靠按新权重重放一遍
        │
        └─ 某段不可达 / 重放不可行 → 退回全量重算（usedIncremental = false）
```

## ④ 一页表：结构 → 承载什么 → 复杂度

前提：**n** = 节点数（30）、**m** = 有向边数（106）、**deg** = 某点出度、**m_task** = 订单数（25）、**s** = 堆内条目数。

| 结构 | 承载什么 | 关键操作与复杂度 | 替代了谁 |
|---|---|---|---|
| `LogisticsGraph` | 节点表 + 邻接表 `vector<vector<Edge>> out_` | `indexOf` **O(n)**（线性扫描，无映射表）；`removeNode` **O(n+m)**（入边分散） | 存储用容器允许；查找/遍历手写 |
| `MinHeap` | Dijkstra 取最小 | `push`/`popMin` **O(log s)**；空堆 `popMin` 返回 false 且不改出参 | `std::priority_queue` |
| `Dijkstra` | 单源最短路 + 前驱数组复原 | `dist`/`previous` 各 O(n)；**惰性删除**使总时间 **O(m·n + m·log m)** | 松弛与堆逻辑手写 |
| `CostMatrix` | 全源最短路（V×V×3），并**统一乘车辆因子** | 建表 V×3 次 Dijkstra；查询 O(1) | 每个候选位置对现算最短路 |
| `pair-insertion` | 把订单的 (A,B) 对插到最省位置 | 单请求 **O(n²) 位置对 × O(n) 重放 = O(n³)**；m_task 张 ⇒ O(m_task·n³) | 贪心"选最近邻"（会在紧窗单上迟到） |
| `repairRoute` | 普通段有界 relocate | O(R·m_task·n³)，R ≤ 3；某轮无改进即停 | 全量重跑构造 |
| `finalize` | 把 `stops` 展平成 `nodes` 视图 | O(节点数 + 停靠数)，**只此一处生成** | — |
| `IniFile` | 手写 INI 解析，报错带行号 | 解析 O(L·r)；`findValue` O(r) | 第三方 INI 库 |

**为什么不用邻接矩阵**：n=30、m=106 是稀疏图（无向道路对仅 56），矩阵 900 格绝大多数为空，且每格要放 3 个权重。
**没有 decrease-key 怎么绕过**：松弛成功就压新条目、旧条目留着，弹出时 `currentDist > dist[current]` 就丢掉（堆条目 ≤ m）。

## ⑤ 三策略差在哪

同一份 `shortestPath`，**只在 `pickWeight` 处换维度**，没有三套算法。
数据生成时 `cost` 按**道路等级**差异化（主干道快而贵、支线慢而便宜），不是 `cost = dist × 常数`——否则"最低成本"会恒等于"最短距离"。

| 策略 | 距离 km | 完工耗时 min | 成本 元 | penalty | 停靠 S / 动作 A |
|---|---|---|---|---|---|
| distance | **139.900** | 429.000 | 172.970 | 0 | 28 / 50 |
| cost | 145.400 | 449.500 | **160.260** | 0 | 32 / 50 |
| time | 170.400 | **378.200** | 243.090 | 0 | 30 / 50 |

**口径**：#43 已提交基线实测，2026-11-24，三车 V01/V02/V03（`tests/plan_golden.h` 单一真值表）。三策略两两不同、各自在自身目标上最优；
**没有「趟数」这一列了**——多趟机制已退役，**每车一条连续路线**（不是全队一条）。取法：`./build/app --plan-summary distance|cost|time`（**9 行**：车队 2 + 每车 3 + 超时 1 + 每车路线 3）。
**逐车 63 项**：V02 与 V03 五个参数完全相同 ⇒ 车队级 13 项对「谁跑哪些单」失明，必须逐车冻结（ADR 0008）。
