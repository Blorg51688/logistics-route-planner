## 2. 领域模型

> **来源**：[#21](https://github.com/Blorg51688/logistics-route-planner/issues/21) resolution｜**权威落盘**：[GLOSSARY.md](../../../GLOSSARY.md)「订单与优先级 / 停靠点与路线 / 车辆 / 节点角色」四节 + [ADR 0002](../../adr/0002-all-orders-pickup-delivery.md)

### 2.1 四个拍板分叉（ADR 0002 正文）

| # | 决定 | 一句话 |
| --- | --- | --- |
| Q1=A | **合并停靠** | 同一节点既是某单取货点、又是另一单送达点时合并为**一次停靠**：取货动作集 + 送达动作集，停靠内**先卸后装**；窗口与 penalty 只由送达单决定。 |
| Q2=B | **硬优先** | 路线中**全部紧急停靠排在全部普通停靠之前**；紧急队列**严格 FIFO**；普通动作唯一例外是**顺路交货**。 |
| Q3=新案 | **停靠零耗时** | 停靠不消耗时间（`departure = arrival`）；耗时只来自**行驶**与**早到等待**（等待计入总耗时、不计 penalty）。`service_time_min` 不参与任何计算。 |
| Q4=A | **紧急阶段不顺路取货** | 紧急阶段只做紧急动作 + 已在车普通货的**顺路交货（仅交付）**；普通取货留到普通阶段，必要时重访该节点。 |

### 2.2 术语与语义（以 GLOSSARY 为准，本文只列开工必读的几条）

- **订单 = 取送单**：全体订单统一 A→B；**A 无窗口、不计 penalty**，**B 带送达窗口**、迟到记 penalty。旧「普通配送单＝仓库取货」语义**已废弃**。
- **仓库 = 基地**：不供货、无库存，只是出发与返回点。**中转站**只存车辆实际卸下的货，容量不限；站内不存在无主库存。
- **路线 = 单条连续路线**：基地出发 → 依次访问各停靠点 → 返回基地。旧「趟（Trip）/ 多趟分批」**已退役**（本文与代码里再出现 `Trip` / `multiTripPlan` 即属未迁移，见 §7 MC-A01）。
- **载重 = 路线前缀在车量**：约束「任一时刻的在车货量 ∈ [0, C]」，**不约束总需求**。默认数据集总需求 516kg > 200kg 容量且完全合法（§3.5）。
- **停靠点数 / 动作数 / 取送对数**：停靠点数 = 实际停下次数（重访计两次）；动作数 = 取货动作 + 送达动作（恒 = 2 × 取送对数）；取送对数 = 被服务的订单数。三者定义见 GLOSSARY「停靠点与路线」，指标口径见 §6。
- **阶段（phase）**：路线被硬优先切成的两段——**紧急段** / **普通段**。停靠明细「阶段」列与不变量 4/7 的断言都以它为口径（`4e27deb` 落盘）。

### 2.3 与 ADR 0001 的关系

ADR 0002 **Supersedes** ADR 0001 的**适用范围**（0001 只把紧急单改为取送；0002 把全部订单统一为取送并退役多趟）。0001 的「中转站＝降载暂存点」语义**继续有效**，扩展为「只存车辆实际卸下的货」。→ 实现时不要把 ADR 0001 的「紧急单独立成趟」当现行口径。

**出处**：ADR 0002 全文（含已否决备选：分两次停靠 / 数据禁止 A=B / 软优先 / 只改插单时机 / 三种服务时间计时）。

### 3.2 十条校验（一律 `第 N 行 [orders]: <具体原因>`，首个错误即返回）

| # | 规则 | 报错文案 |
| --- | --- | --- |
| 1 | 字段数必须 **7**；多/少都报错 | `需要 7 个字段，实际 K 个: <原文>` |
| 2 | `ID` 非空且**全局唯一** | `订单 ID 为空` / `订单 ID 重复: <ID>` |
| 3 | `pickup`、`delivery` 必须存在且 `type = delivery` | `取货点不存在: <ID>` / `取货点必须是配送点: <ID>`（delivery 同构） |
| 4 | `pickup ≠ delivery` | `取货点与送达点不能相同: <ID>` |

| 6 | 窗口**必填**、`HH:MM`、`start < end`（窗口只属送达点 B） | `时间窗口格式应为 HH:MM` / `窗口起必须早于窗口止` |

### 3.5 初始数据集（25 单）的设计事实

**生成规则（确定性，由生成器算出、不手写）**：

- 每子网络 3 个角色：**枢纽 H** = 子网络内距本子网络中继站最近的配送点（并列取 ID 小）→ `sub1 D08 / sub2 D14 / sub3 D20`；**回程起点 R** = 子网络内距 W01 最近且 ≠ H → `sub1 D01 / sub2 D05 / sub3 D23`。

- **回程单 3 条**：`pickup = R`，`delivery = H`。
- **kg**：派送单 sub1 = 20 / sub2 = 24 / sub3 = **19**（同子网络等重）；回程单统一 20。

## 4. 算法（单条连续路线）

> **来源**：[#18](https://github.com/Blorg51688/logistics-route-planner/issues/18) resolution（§2–§13 为条目本体，§14 为调研依据对应，§15 为七组边界走查）｜选型依据 [pdp-multivehicle-research.md](pdp-multivehicle-research.md) §2.1(b)/§2.4/§3.1

### 4.1 路线结构

```text
[基地] → 紧急阶段（紧急单 A/B 对，订单级 FIFO 整单串接）
       → 普通阶段（普通单 A/B 对，EDD 插入 + 取回必做停靠）
       → [基地]
```

- 紧急阶段：只做紧急动作 + 顺路交货（仅交付）+ **降载卸货停靠** + **FIFO 强制重访停靠**。
- 普通阶段：普通单取/送对 + 暂存**取回**停靠。
- 构造器 = **penalty 先的 cheapest pair-insertion**（不是最近邻；最近邻只作基线/叙事）。
- 目标 = 字典序 **(Σpenalty, 当前策略权重, 稳定 tieKey)**；时间推进恒用所选 leg 的**实际耗时**；停靠零耗时。
- 不可行只在：A/B 不可达、`q > C`、`q ≤ 0`、`A == B`、降载后仍缺载重且兜底无解。

### 4.2 候选集（两层）

| 层 | 内容 |
| --- | --- |
| **请求候选** | ① 未服务订单的 (A,B) 对（普通单参与位置枚举；**紧急单不枚举位置**，按 FIFO 追加到紧急段尾）② 暂存货**取回**（暂存非空时普通段的**必做单点停靠**，无窗口）③ **降载卸货**（触发时插在触发取货停靠之前的支持停靠） |
| **位置候选** | 普通阶段内的全部 `(i, j)`（A 在 i 前、B 在 j 前，`j ≥ i`）；同节点并入既有停靠；紧急单只追加、不枚举 |

「在车已取未送 B」**不是**可自由选择的下一站，而是**约束**（B 必须落在其 A 之后，可并入同节点既有停靠）。

### 4.3 可行性检查（F1–F7）

```text
F1 每张订单恰好服务一次（一次取货 + 一次送达）
F2 每张订单 A 的停靠索引 < B 的停靠索引（A≠B）
F3 前缀载重：逐停靠先减（deliveries + offloads）再增（pickups + reclaims），全程 ∈ [0, C]
F4 硬优先：无普通停靠先于紧急停靠；紧急阶段无普通取货动作
F5 订单级 FIFO：U_k 的送达停靠索引 ≤ U_{k+1} 的取货停靠索引；
   合并停靠内先送达后取货；同阶段同节点至多一次停靠，例外仅 FIFO 强制重访
F6 暂存：每张暂存单恰一次取回；取回索引 < 该单送达索引；全局至多一堆、锁站；计划结束为 0
F7 时间与逐单 penalty；任一段不可达 ⇒ false
```

### 4.4 时间与等待口径（逐单窗口的直接推论）

```text
raw        = departure(prev) + travelTime(prev, s.node)
wait       = s.deliveries 为空 ? 0 : max(0, max{ ws_i : i ∈ s.deliveries } − raw)
arr        = raw + wait
penalty_i  = max(0, arr − we_i)      # 逐单累加，停靠无「合并窗口」
departure  = arr                      # 停靠零耗时
```

- 等到**全部送达单窗口都开启**（一个停靠只有一个到达时刻）。
- **顺路交货只在不增加等待时并入**：普通单的 `ws` 晚于该停靠原等待点则本次不交付，留到普通阶段。
- `arrival == we` **不算迟到**。

### 4.5 主构造与四个阶段

| 步骤 | 规则 |
| --- | --- |
| 排序 | 紧急单 FIFO 键 =（到达事件刻, 插入序）；普通单 **EDD**（窗口止升序，同窗止按 ID 升序） |
| 紧急段 | `appendUrgent`：装不下先降载 → 在紧急段尾追加 A、B（同节点合并时停靠内先送前单再取后单）→ 顺路交货 |
| 普通段 | `insertNormal`：全位置对枚举 → 取 key 最小 → 失败则先 `repair(R≤3)` 重试 → 仍失败走**全量兜底** → 仍失败走**降载** → 仍失败拒绝并报原因 |
| 修复 | 有界单请求 relocate，`R ≤ 3`，某轮无改进即停；**只动普通阶段**（紧急段对 relocate 恒等） |
| 兜底 | 从车辆当前 pos/now/在车货出发，对剩余未服务订单重跑完整构造；两版按 key 取优（**penalty 一票否决＝第一键**）；**不做周期性全量重算** |

### 4.6 降载与取回（最后手段）

| 维度 | 定稿 |
| --- | --- |
| 触发 | pair-insertion（含修复/兜底）找不到任何可行位置、且不降载就无法服务该取货动作；紧急与普通取货都适用；**不主动为「更优」进站** |
| 选货 | 只卸**整张普通订单**，绝不卸紧急货，**不卸目的地恰为触发紧急停靠点 A/B 的货**；在车普通单按 kg 降序（同 kg 按 ID）取前缀直到 Σkg ≥ need；仍不足 ⇒ 降载失败 |
| 选站 | 已有暂存 ⇒ 锁站不重选；否则对每个中转站构造「降载版整条剩余路线」，可行者按 key 取优，并列按站 ID；站容量不限 |
| 取回 | 普通阶段的**必做单点停靠**，位置由同一 pair-insertion 评价器选 key 最小；硬约束：**先于每张暂存单的送达**；**不得落紧急阶段** |
| 堆数 | **全局至多一堆、锁站**；后续降载并入同一站同一堆；锁站不可达 ⇒ 全量兜底；兜底仍不可行 ⇒ 拒绝该单并报原因 |
| custody | 记录 (orderId, station, kg, offloadTime, reclaimTime)；送达前校验来源；计划结束暂存必须为 0 |

### 4.7 十二条不变量（验收直接断言，迁移清单 MC-B06 已给逐条守卫落点）

1. 每张订单恰好服务一次（一次取货、一次送达）；不可行时给原因，**不得丢单**。
2. 每张订单 A 的停靠索引 < B 的停靠索引。
3. 任一时刻 0 ≤ 在车量 ≤ C；停靠内先卸后装，峰值按「卸后/装后」较大者。
4. 硬优先：无普通订单停靠先于紧急订单停靠；紧急阶段无普通取货动作。
5. 订单级 FIFO：U_k 的送达停靠不晚于 U_{k+1} 的取货停靠；合并停靠内先送达后取货。
6. 紧急阶段**同刻至多一张紧急单在车**。
7. 同阶段同节点至多一次停靠；唯一例外是 **FIFO 强制重访**，且重访停靠只含该单的一个动作。
8. 停靠零耗时 `departure = arrival`；早到等待计入耗时、不计 penalty；`arrival == we` 不算迟到。
9. penalty **逐单**：每张送达单按自己的 `we` 计，停靠无合并窗口。
10. 暂存守恒：站内暂存 = Σ卸入 − Σ取回；计划结束为 0；全局至多一堆、锁站。
11. 取回先于送达：每张暂存单的取回停靠索引 < 其送达停靠索引。
12. 输出确定性：同输入（含策略）必得同一路线与同一 key；并列按稳定 tieKey。

> **规格二前向指针**：不变量 5/6 在**转运版**被 ADR 0004 精确化为「U_k 的送达**时刻** ≤ U_{k+1} 的取货**时刻**」「同刻至多一张紧急单处于**已取未送**（在车**或**在站）」。规格一单车、无转运，两条表述等价；实施规格一时按本文原文断言。

### 4.8 复杂度与目标规模

| 项 | 复杂度 |
| --- | --- |
| 全源最短路 | 手写 Dijkstra × V × 3 种权重，存 V² 矩阵（距离/耗时/成本） |
| 单请求 pair-insertion | O(n²) 位置对 × O(n) 重放 = **O(n³)**；m 单 ⇒ O(m·n³) |
| 修复 | O(R·m_n·n³)，R ≤ 3 |
| 降载 | O(|T|·n³)（每候选站构造一次） |
| 全量兜底 | 同构造，仅在不可行/不可达时触发一次 |
| 内存 | O(V²) 矩阵 + O(n) 路线 |

**目标规模（Q6=A）**：m ≤ 50 单 / n ≤ 100 停靠点；**全量位置对扫描、不裁剪**（n > 100 再谈 top-k，本次不做）。

### 4.9 边界走查

七组（容量压力 / FIFO 合并 / FIFO 强制重访 / 顺路交货 + 逐单窗口 / 取回位置约束 / 封路不可达 / 不可行）见 #18 resolution §15。**其中「④ 顺路交货 + 逐单窗口」正是 Q14=A 要修掉的掩盖**：并集窗口会让紧急单迟到被普通单宽窗吞掉。

## 5. 事件模型与动态订单

> **来源**：[#24](https://github.com/Blorg51688/logistics-route-planner/issues/24) resolution｜事件刻结算纪律见 [sim-time-events.md](sim-time-events.md)（D24）

### 5.1 四类事件

| 事件 | 默认概率 | 动作 | 生单 | 重规划 |
| --- | --- | --- | --- | --- |
| 路况 | 67.5% | `simulateTrafficChange`：`round(ratio×E)` 条边，耗时 ×(1+[20%,50%]) 或清回 base；`baseTimeMin` 不变 | 否 | 仅当受影响边在**当前路径**且增幅 ≥20% ⇒ D22 增量；否则只重绘 |
| 普通订单 | 22.5% | 按 R1–R9 刷 1 张普通单 | 是 | §4.5 普通段插入链 |
| 紧急订单 | 7.5% | 按 R1–R9 刷 1 张紧急单 | 是 | §4.5 紧急段尾插 |
| 道路封闭 | 2.5% | 随机**非桥**边**双向永久**删除；无非桥边 ⇒ 播报无动作 | 否 | leg 增量 → 全量兜底，字典序取优 |

「新客户」**随机事件退役**（`SimEventKind::NewCustomer` → `NormalOrder`，**保位改名**——位次即抽签扫描顺序，动顺序会让固定种子的随机串整条变）；动态加节点改由**手动动作**承担。

### 5.2 概率语义

概率 = `w_i / Σw`（Σ = 四键派生权重之和）。默认组合（高 27 / 中 9 / 低 3 / 极低 1）Σ=40 ⇒ 67.5/22.5/7.5/2.5%。改任意等级后仍归一化，四项和恒为 1（示例：封路改 medium ⇒ 27/9/3/9，Σ=48 ⇒ 56.25/18.75/6.25/18.75%）。这是**既有行为的契约化**（`pickEvent` 本就只累加正权重、掷一次 `roll ∈ [1, Σ]`），不是新机制。

### 5.3 事件触发与结算（沿用 D24）

- 事件刻：`nextEventMin = ((now / interval) + 1) × interval`，绝对对齐；`interval = event_interval_min`（现 15）。
- **每刻恰 1 次抽签**，**1 次抽签恰消耗 1 次随机数**（含全零权重的保底分支）。
- 结算挂在**软件时间前进**上：`onAdvanceStop` 与 `onAdvanceMoment` 移动后都调 `settleEventsUpTo(now)`；跨多刻就连续结算；终点后不再结算。
- **等价性纪律**：一次推进一刻 == 逐个推进到同一时刻（事件串、抽签次数、订单/图状态一致）⇒ 每类事件随机消耗次数必须固定（抽签 1 次 + 动作固定次数：紧急/普通刷单各 3 次 = A、B、kg；路况 1 次；封路 1 次）。**这就是 A/B 必须「一次抽出」而非拒绝采样的原因**。

### 5.4 刷单规则 R1–R10

| # | 规则 |
| --- | --- |
| R1 | 1 个事件刻最多生 **1 张单**；路况、封路不生单 |
| R2 | 候选 = 当前图**全部配送点**；A 均匀、B 在剩下 n−1 个里**一次**抽出（固定消耗 2 次随机数），A≠B；不限子网络、不看服务状态 |
| R3 | kg：普通 **3–15**、紧急 **3–10**，**整数**；同时满足 `q < min(capacity_kg)` |
| R4 | 窗口：t = **事件刻**；普通 `[t, 24:00]`、紧急 `[t, min(t+60, 24:00)]`；A 无窗口 |
| R5 | 来源四类 `initial / event_normal / event_urgent / manual_customer`，前缀 `O / N / U / C`；**运行时字段，不进 `[orders]` 七列契约** |
| R6 | 自动刷单额度：普通 **6**、紧急 **2**；计数 = **事件来源且未送达**（含在车）；初始/手动**不计**；满额该类别抽签前置 0 权重；手动动作不受限；**代码常量、不加配置键** |
| R7 | 两类都满 ⇒ 只抽路况/封路；仍每刻 1 抽、不空刻；播报注明「某类已满」 |
| R8 | 插入：普通 → §4.5 普通段链；紧急 → 紧急段尾插（订单级 FIFO） |
| R9 | 通过输入校验即并入订单集合；**插入失败照实播报并保留未服务，不丢单** |
| R10 | 手动「模拟新客户」= 建节点 X + 普通单 `A=随机现有配送点 → B=X`（3–15kg、`[now,24:00]`），只手动、不入事件池、不受上限、走同一插入链 |

**Q8 处置**：抽签前**只**把「已达上限」的类别置 0；抽中后不可执行（无非桥边、配送点 <2 等）仍算抽中、播报失败原因、**不重抽**（保住等价性断言）。

### 5.5 六条执行细化（resolution §1.9，均不推翻拍板）

窗口基准 = 事件刻而非结算时刻；上限只数「事件来源」；上限用常量；订单带来源标记与 ID 前缀；刷单插入失败仍持久化；手动新客户方向 `B=X`。

## 6. 指标与验收口径

> **来源**：[#29](https://github.com/Blorg51688/logistics-route-planner/issues/29) resolution｜权威落盘 [ADR 0006](../../adr/0006-metric-definitions.md)

### 6.1 五项汇总 + 三项新增

| 指标 | 定义 | 数据来源 |
| --- | --- | --- |
| 总距离 | Σ 各边 `distanceKm`（与车型无关） | `RoutePlan::totalDistanceKm`（已有） |
| 总耗时 | 规格一 = 该车 `返回基地 − 发车` | `RoutePlan::totalTimeMin`（已有） |
| 总成本 | Σ 各边 `costYuan × cost_factor` | `RoutePlan::totalCostYuan`（已有） |
| 总 penalty | Σ **逐单** penalty `max(0, arrival − we_i)` | 字段已有，但底下 `Stop::penaltyMin` 是**停靠级**（合并窗口），需改逐单 |
| **停靠点数 S** | 车辆实际停下的节点访问次数（重访计两次；含降载/取回停靠） | `plan.stops.size()`（已有） |
| **动作数 A** | 取货动作数 + 送达动作数；**结构性恒等 A = 2 × 取送对数**；降载/取回**不是**取送动作 | **无当前字段**（`Stop` 不带动作集） |
| **取货准时率** | 「不注定迟到」判据，见下 | **无当前字段** |
| **送达准时率** | 逐单，紧急/普通分列，分母 0 记「—」 | 需逐单 arrival 与 `we` |
| **平均在车货量 / 利用率 / 峰值** | 时间加权，见下 | 可从停靠序列 + 装卸量 + 到达时刻推出，需修 `remainingLoadKg` 语义 |

**取货准时判据（零新参数）**：`t_pick + shortestTime_vehicle(A_i → B_i) ≤ we_i`，其中 `shortestTime_vehicle` 是**该车缩放后**的耗时（标量缩放下 argmin 不变，等于基础图 A→B 最短耗时 × `time_factor`）；`== we` 算准时。

**送达准时率**：`arrival(B_i) ≤ we_i`；分母 = 已规划订单数；紧急/普通分列；**分母为 0 显示「—」**。

**平均在车 / 利用率**：`平均 = Σ_段(该段在车量 × 该段时长) / 总运行时长`；`利用率 = 平均 ÷ 该车 capacity`；并列**峰值**。段 = 相邻两停靠点之间（含首段「基地→首停靠」与末段「末停靠→基地」）；停靠零耗时 ⇒ 段内恒定 ⇒ 分段积分是**精确**的。首末空载段**计入分母**（这正是它能反映空驶的原因）。降载/暂存/转运的货**不算在车**，取回/接管后重新计入。

> **为什么不是「取送对数」而是「动作数」**（本人拍板，偏离票面字面）：基准数据上停靠点数 == 取送对数 == 25，两个相同数字并列无信息；动作数 50 与停靠 25 的比值 **0.5** 才是「合并把访问次数砍了一半」的可见证据。取送对数保留为**报告用口径**。

### 6.2 数据来源缺口（实施必须补，归 #20 的 MC-A03/A04）

1. `Stop` 无动作集 → 需补 `pickups[]` / `deliveries[]`（订单 ID 列表）。动作数、取货准时率、逐单送达准时率**全部依赖它**。
2. `Stop::penaltyMin` 是停靠级 → 逐单口径下需能按单读 penalty（最小改法：`deliveries[]` 每项带自己的 `penaltyMin` 与 `late`）。
3. `Stop::remainingLoadKg` 语义要改为「离开该站时的**在车货量**」（= 到达在车量 − 送达 − offload + 取货 + reclaim）。
4. 取货时刻要能按单查（补 `pickups[]` 后 = 该停靠的 `arrivalMin`）。
5. A→B 最短耗时**按车**取（每单一次单源最短路，25 单可忽略；**不要**建每车 V² 矩阵）。

### 6.3 摘要行四行格式（定稿）

```text
总距离 <d> km | 总耗时 <t> min | 总成本 <c> 元 | 总 penalty <p> min | 停靠 <S> 站 · 动作 <A> 次
取货准时率 <P1>%（<x>/<y>） | 送达准时率 <P2>%（<x>/<y>；紧急 <Pe>% · 普通 <Pn>%） | 平均在车 <L> kg（利用率 <U>% · 峰值 <K> kg）
超时订单：<订单ID>@<节点ID>(+<n>min)、… （无则「（无）」）
路线 <N0> <N1> … <Nk>
```

- 精度：距离/耗时/成本 3 位小数；百分数 1 位；平均在车/峰值 1 位；penalty/停靠/动作整数。
- 分母 0 的率打印 **`—`**（不是 0%/100%）。
- 第 3 行从「超时停靠点」改为「**超时订单**」（逐单）；第 4 行「路线 …」**新增**（oracle 算术对拍需要 app 输出的节点序列；GUI 不显示）。
