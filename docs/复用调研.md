**核心算法一个都不能复用**（课程硬性要求，且这本身就是考察点）；**GUI 层有一处大复用**（Qt `QGraphicsView`）；施工前先读参考实现避免写错，但代码自写。

## 1. 硬约束：核心算法必须自写

## 2. 该复用的

### 2.1 Qt `QGraphicsView` / `QGraphicsScene` —— 收益最大的一处

这是平台原生能力（梯子第 4 级）。自己写 2D 画布 = 把坐标变换、缩放平移、命中测试、重绘裁剪、抗锯齿全部重造一遍。**Qt6Widgets 已安装**。

官方示例 `elasticnodes`（[Qt 文档](https://doc.qt.io/qt-6/qtwidgets-graphicsview-elasticnodes-example.html)）给出了可直接照搬的**惯用法**：

**节点图元**（`examples/widgets/graphicsview/elasticnodes/node.cpp`）
- 继承 `QGraphicsItem`，实现 `boundingRect()` / `paint()` / `shape()`
- `setFlag(QGraphicsItem::ItemIsMovable)` + `setFlag(QGraphicsItem::ItemSendsGeometryChanges)`
- 覆写 `itemChange(ItemPositionHasChanged, ...)` → 通知关联边重算几何，实现「拖动节点时边跟随」
- 覆写 `shape()` 返回精确 `QPainterPath` 命中区域（而不是整个 boundingRect）

**有向边箭头**（`examples/widgets/graphicsview/diagramscene/arrow.cpp`）
- 箭头多边形几何，约 5 行数学：

```cpp
const double angle = std::atan2(-line().dy(), line().dx());
const QPointF p1 = line().p1() + QPointF(std::sin(angle + M_PI / 3) * arrowSize,
                                         std::cos(angle + M_PI / 3) * arrowSize);
const QPointF p2 = line().p1() + QPointF(std::sin(angle + M_PI - M_PI / 3) * arrowSize,
                                         std::cos(angle + M_PI - M_PI / 3) * arrowSize);
QPolygonF head;
head << line().p1() << p1 << p2;
painter->drawPolygon(head);
```

- 用 `QLineF::intersect()` 把箭头停在节点边界而非圆心，视觉上不穿进节点
- 覆写 `shape()` 并用 `QPainterPathStroker` 给细线加宽度 —— 否则 1px 的线几乎点不中（本项目的边需要点击/高亮，这点必须做）

**为什么这几段可以抄**：它们是 Qt 惯用法，不是被考察的算法，抄了不违反课程要求，且能省掉大量调试。许可证为 `LicenseRef-Qt-Commercial OR BSD-3-Clause`，法律上可复用。

### 2.2 不需要任何图布局算法（重要）

force-directed / graphviz / 层次布局**统统不需要**——`config/default.ini` 已为 30 个节点提供了 (x, y) 坐标，直接读坐标绘制即可。

> 这一条省掉了一个依赖和一大块复杂度。

### 2.3 题目内部的自复用（比外部复用更重要）

需求要求「最短距离」和「最低成本」两种策略。**不写两份 Dijkstra**，而是把权重维度做成枚举参数，一份实现服务两种策略——这是本题里最重要的一处「不重复造轮子」。`设计.md` §5.1 已如此定义。

### 2.4 Qt6Test（留给 GUI 测试）

本机 `/usr/lib64/cmake/Qt6Test` 可用，是官方测试框架。将来给 GUI 层写测试时用它。
**但核心层测试保持不依赖 Qt**（`设计.md` §6），现有 20 行的 `tests/test_util.h` 已够用，不为它引入框架。

## 3. 找到了但不采纳

| 来源 | 不采纳的理由 |
|---|---|
| GitHub 上约 20 个「dijkstra visualization qt」仓库 | 全是 ★0–1 的小型**可视化 demo**（选起终点、播放最短路动画），没有载重/时间窗/动态插入；质量与维护度都不值得依赖 |
| [Solomon VRPTW benchmark](https://github.com/SelinHulagu/vrptwq-solomon-instances) | 时间窗车辆路径的**标准数据集**，学术上权威；但格式与我们自己的 INI 不同，转换成本 > 收益，且我们的窗口本就是演示用 |
| `boost::graph` / LEMON / OGDF | 课程禁用 + 本机无 devel 头文件 |
| Qt6Charts | **未安装**；本项目也不需要图表 |
| 第三方 INI / JSON 解析库 | 课程明确禁止（`设计.md` §10 禁止事项），且 `IniFile` 已手写完成 |
| 一次性默认数据生成脚本 | 已用完即弃，产物入库、脚本不入库 |

## 4. ⚠️ 抄袭风险（必须说清）

课程原文：

> 若发现作弊者，作弊双方均按学籍管理办法处理。

- Qt 官方示例是 BSD-3-Clause，**法律上**可复用，且它不是「同学代码」，与课程所说的抄袭不是一回事。
- 真正的风险在**验收与答辩**：`设计.md` §3 记录「验收时指导教师会现场变更需求，要求现场修改源代码」。抄来的代码一旦讲不清、改不动，当场露馅。
- **因此的界线**：
  - ✅ 复用**框架**（`QGraphicsView`）与**惯用法**（箭头几何、`itemChange` 联动、`shape()` 命中区）
  - ❌ 不整文件粘贴示例代码
  - ✅ 所有业务类（`NodeItem` / `EdgeItem` / `MainWindow` / `GraphScene`）自己写
  - ✅ 报告与代码注释中注明「箭头绘制参考了 Qt diagramscene 示例」

## 5. 对下一步（手写 MinHeap + Dijkstra）的结论

**无任何可复用代码**——必须自写，这是课程考察点本身。但先读参考实现，避免踩经典坑：

参考：[cp-algorithms — Dijkstra](https://cp-algorithms.com/graph/dijkstra.html)（权威，讲清 INF、不可达、松弛条件）

要防的经典 bug：

1. **不可达必须返回明确标记**，不能让 `INF` 伪装成真实距离继续参与累加（`设计.md` §5.1 已要求「不可达时返回明确标记」）。
2. 距离数组用 `INF` 初始化，松弛条件写成 `if (candidate < dist[to])`。
3. 必须有 `prev[]` 前驱数组，否则算得出代价但还原不出路径。
4. 三权重维度用**枚举参数**复用同一份 Dijkstra，不写三份。
5. 手写堆需要 `decreaseKey` 或「重复入堆 + 弹出时跳过过期条目」。**推荐后者**：不必维护下标映射，实现更简单。
   > **实施后更正（变异测试结论）**：其中「跳过过期条目」这一步是**性能优化，不是正确性必需**。因为堆总先弹出更小的 key，节点的正确条目必定先于其旧条目被处理，旧条目算出的候选值不可能更小。去掉守卫后全部测试结果不变。真正的收益在于**堆不需要 `decreaseKey`**，而不是那个守卫本身。
