# 测试用例表

> 本表是《数据结构课程设计》报告【测试】章的备料，用户写报告时自行取用。
> 每条用例给出：**用例 → 输入 → 期望结果（标口径）→ 依据**（哪个测试文件里的哪个检查、或哪条命令的实测输出）。
> 本表不替代 `docs/设计.md` §14（测试分层与期望值来源），那边讲"为什么这么测"，这里讲"测了什么"。

## 口径说明（先读，避免两个数混用）

| 口径 | 数值 | 怎么来的 |
|---|---|---|
| `ctest` 目标数 | **20** | `cd build && ctest -N` 报的 `Total Tests: 20`（9 个测试二进制 + 5 个自检/守卫 + 6 个向导相关，含 Qt6 缺失时自动跳过的项） |
| 断言/检查项总数 | **829** | 9 个测试二进制**各自自报**的检查数之和：`core_tests` 101 + `config_tests` 223 + `minheap_tests` 28 + `simevent_tests` 27 + `dijkstra_tests` 19 + `routeplanner_tests` 206 + `integration_tests` 110 + `traffic_tests` 83 + `graphedit_tests` 32 = **829** |

**这两个数不能相加、不能互相替代**：20 是 ctest 的执行目标数，829 是 C++ 二进制内部的 `check()` 计数。
本表中"期望结果"一列标注的口径含义：**已提交基线** = 在 `HEAD`（`git rev-parse HEAD`）上可复现；**工作区未提交修订** = 含工作区未提交改动的实测。

> 实测记录（2026-10-19，口径：已提交基线 `e6eeaf4`）：
> `ctest` 20/20 通过；9 个二进制全部"0 项失败"，合计 829 项检查。

## 二、导致程序错误的用例（错误输入）

| # | 用例 | 输入 | 期望结果 | 依据 |
|---|---|---|---|---|
| E1 | 缺少必需节 | 配置缺 `[edges]` / `[nodes]` / `[vehicles]` / `[orders]` 中任一个 | 解析失败并指出缺哪一节 | `tests/config_tests.cpp` 错误输入段 `testErrorCases`：`expectParseFailure(..., "缺少 [edges] 节")` 等 |
| E2 | 字段数不符 | `[nodes]` / `[edges]` 行字段数不对 | 解析失败并指明哪一节字段数不符 | `tests/config_tests.cpp:testErrorCases` |
| E3 | 未知节点类型 | `[nodes]` 出现未知类型名 | 解析失败 | `tests/config_tests.cpp:testErrorCases` |
| E4 | 配置文件缺失 | 指向不存在的路径 | 加载失败、错误信息非空 | `tests/config_tests.cpp`：`check(!ConfigLoader::load("/nonexistent/path/nope.ini", ...))` |
| E5 | 单订单超过单车容量 | 需求量 > 载重且无法拆分的单 | 判定不可行（而不是静默截断） | `tests/routeplanner_tests.cpp:testSingleOrderExceedingCapacityIsInfeasible` |
| E6 | 不可达配送点 | 订单指向不可达节点 | 判定不可行，且报出具体节点名 | `tests/routeplanner_tests.cpp:testUnreachableDeliveryIsInfeasibleAndNamesTheNode` |
| E7 | 紧急单窗口无法满足 | 紧急单时间窗不可能达成 | 给出警告但仍产出计划（不崩溃、不静默） | `tests/traffic_tests.cpp:testInsertUrgentOrderWarnsButStillPlansWhenWindowCannotBeMet` |
| E8 | 空图删节点 | 空图上 `removeNode` | 返回 false，不崩溃 | `tests/core_tests.cpp:testEmptyGraphBoundary` |
| E9 | 空图上加随机客户 | 空图调用 `addRandomCustomer` | 返回空 ID，图仍为空 | `tests/graphedit_tests.cpp:testAddRandomCustomerOnEmptyGraph` |

> **IniFile 报错行号的覆盖现状（如实记录）**：`src/io/IniFile.cpp:fail` 确实给所有错误拼上"第 N 行"（源码注释 `IniFile.h` 明示"所有错误都带行号"），
> 但 `tests/config_tests.cpp` 的错误用例只断言"错误信息非空"（`check(!error.empty(), ...)`），**没有任何一条断言校验报错文本里带行号**。
> 这是**测试覆盖的空洞，不是实现缺陷**；写报告时如需声称"报错带行号已测"，须先补一条断言（校验 `error` 含 `第 N 行` 字样），否则按"实现具备、测试未覆盖"写。

## 四、守卫类测试（防止回归悄悄回来）

这些不是"程序功能"用例，而是本项目为历史缺陷设的自动化守卫，报告【测试】章可单独列一小节说明"缺陷如何被永久看守"。

| G2 | `wizard_text_lint` / `wizard_claims_lint` | 向导文案里的数字声明与当前数据一致（节点/边/载重等） | `tools/check_wizard_text.py` / `tools/check_wizard_claims.py` |
