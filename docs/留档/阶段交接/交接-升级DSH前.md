## 5. 最容易再踩的坑（**只列会让人白干半天的那几条**）

> 详细根因与修法见 `docs/设计.md` §16 P25 / P34 / P35 / P36 / P37，以及 `.omd/notepad.md` priority 区。

1. **守卫必须证明"真的测到了东西"**。本对话真的写出过一个**空跑**守卫：用一份已被前面步骤改脏的
   配置新建窗口 ⇒ 计划为空 ⇒ 断言退化成"0 站 vs 0 站"却**显示通过**。→ 加**前置断言**。
2. **守卫绝不能"挂住"，只能"失败"**。任何自写循环都要有**迭代上限** + **无进展即退出**；
   否则回归是让 `ctest` 超时，而不是报红。
3. **守卫别写成循环化的**（本对话踩过）：曾用「标为'出仓装车'的行必须已满载」守"出仓必满载"，
   而那个标签与"是否装过货"**同源** ⇒ 把修复撤掉后该趟改标成别的、守卫**照样通过**。
   改用**非循环**判据（"标为'接着送'的趟起点绝不能是仓库"）才咬得住。
4. **"从计划反推物理事实"是本项目反复栽的根因**（P25）。`VehicleState` 是唯一物理源；
   重规划只读不写。**新加任何物理量，先问"它会不会在重规划后变错"。**
5. **不要预取"固定步数"来推进**（P35/P36 类）：重规划会重置游标，事先算好的步数随即失效；
   要按 `atRouteEnd()` 这类**状态**推进，并保留上界。
6. **改 UI 文案会被硬编码的期望表头拦住**（`cli_ui_probe` 里存着停靠明细的表头与动作名下限）。
   这不是回归、是守卫在起作用 —— **同步更新那份期望**，不要为了通过而放宽守卫。
7. **包装脚本里构建输出一律进 stderr**（`cmake --build` 会把 `Built target ...` 写进 stdout）。
