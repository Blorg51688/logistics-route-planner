## 1. M1 异构调度（默认数据，零额外操作）

**演什么**：三策略各自把哪些簇给哪台车、逐车指标差异、完工耗时 vs 车时合计。

```bash
for s in distance cost time; do echo "==== $s"; ./build/app --plan-summary $s 2>/dev/null; done
```

**现场操作（GUI）**：

1. 重启进程（干净状态）。状态栏「软件内时间：06:30」；右侧只有**一个「信息」dock**，内含三个标签页——**① 车辆**（默认页；4 行一车一行：V01 已收工 / V02·V03·V04 空闲，载货 0 / 额定 160 或 400）、**② 订单**、**③ 中转与配送网**。点标签随时切换，**同一时刻只显示一页**；画布在 1360px 窗口下恢复 ≥900px。底部「日志」dock **只有一页「日志」**（#62 退役了「路线与停靠」）；路线摘要与逐车指标在规划完成时写进日志开头：**「路线摘要：策略 …」一行 + 「逐车指标 Vxx：…」四行**。
2. 策略 = 最短距离 → 在**日志开头**记录「路线摘要：」与「逐车指标 Vxx：」四行；画布上**每车只有「当前位置 → 下一目标」的箭头**，慢车同为青色、快车洋红，各车所在节点外有环（同节点多车同心错开）；**悬停环可读车号与角色**（如 T03「车辆环： V01（快车） V04（慢车）」，说明这是快车与本簇慢车叠加，不是慢车越簇）；**选中车辆表某行**的车加粗（点哪行画布高亮哪台）。
3. 策略 = 最低成本 / 最短耗时 → 目标箭头与逐车指标都随策略变（每车各按自己的键规划）；颜色仍按角色两色不变。
4. 在日志「路线摘要：」行里指认 **均衡度（峰值利用率极差）**；指认「完工耗时 ≠ 车时合计」两个数字（同一行内并列），说明两个口径不可互替。

**实测关键值（2026-11-25，完整 **11 行**见 AGENTS §3）**：

| 策略 | 总距离 | 完工耗时 | 总成本 | penalty | 停靠·动作 |
| --- | --- | --- | --- | --- | --- |
| distance | 893.300 km | 696.375 min | 2017.200 元 | 0 | 28 · 50 |
| cost | 894.300 km | 696.375 min | 2016.960 元 | 0 | 28 · 50 |
| time | 900.400 km | 664.750 min | 2034.000 元 | 0 | 28 · 50 |

> **cost 策略 penalty 3 是真实后果，不是缺陷**：`O07@D11(车 V02, +3min)`。职责封闭（#46）后
> V02 只能跑本簇，成本键把某条边换成了更便宜但更慢的路，一单迟 3 分钟。这也是「车级取优」的
> 固有性质：每车各自取优不保证全局 penalty 最小。

逐车 84 项（每车 7 项 × 4 车 × 3 策略）见 `tests/plan_golden.h`；逐车路线（G17）见同名文件 `routeNodes`。
默认数据（规格六 #60 起为**簇内 / 跨簇参半**）上**快车 V01 不接单**（它的活只有站↔站腿）；
`--dump-plan` 的 `ASSIGN V01 空车 0` 是这件事的可核对视图。这一版起账本里**天然有 12 笔
三段接力**（12 张跨簇单），不再需要插夹具才能看到接力。

## 2. M2 跨车转运（**默认数据自带 12 笔三段接力**）

**演什么**：默认数据上就有 12 张跨簇单走三段接力（快车两趟扫掠、每趟一次装 6 单）；
再插一张跨簇普通单 O26 会立刻多出一笔。

### 2.1 现场操作（GUI，4 步）

1. 重启进程（干净状态，默认四车）。
2. 事件注入 →「插入普通订单…」：**A = D08（子网 1）、B = D18（子网 3）、8 kg**
   → 订单表出现该单；日志播报「插入普通订单 O26：D08 取 → D18 送」。
3. 「重新规划」（任一策略）→ 日志出现三段腿的分级播报。
4. 推进一站直到该单送达 → 右侧「信息」dock 切到页③**「中转与配送网」**，下半的**转运账本出现一行**：订单 O26 / 站 T03 / kg 8 /
   卸入 V01 08:52 / 取走 V04 08:52 / 等待 0 / 状态「已送达」。**#62 三态现场判读**：
   ① 卸入后取走前 → 状态「在站」、上半「站内待取走(kg)」> 0；
   ② 取走后送达前 → 状态「在途（Vxx HH:MM 取走）」、同列回到 0（货在车上，不再算站内）；
   ③ 送达后 → 状态「已送达」。三态与「站内待取走」不再互相矛盾。

> **为什么现在默认数据就能演**：规格三把跨簇单**结构上**拆成三段腿（客户1→站A / 站A→站B /
> 站B→客户2），转运由**任务结构**产生，不再依赖「优化器碰巧选中」。规格二那套「三判据门控 +
> 严格字典序更优才启用」已退役（见 `docs/设计.md` §5.9）。

**观察点**：

- **① 三策略都走三段接力**：L1 由**本簇慢车 V02**、L2 由**快车 V01**、L3 由**对簇慢车 V04**
  执行，相邻两段不同车 ⇒ `TRANSIT` 行 `卸入车 ≠ 取走车`。这是「职责表在输出里生效」的证据。
- **② 就绪链单调**：`LEG` 的 readyTime 列（08:00 → 08:42/08:51 → 08:52/09:16）沿接力链递增。
- **③ 期末无在站**：状态「已送达」、`dwell 0`（≤ 60）。
- **④ 策略差异**：distance/time 在 08:52 完成，cost 在 09:16 —— 成本策略下 L2 取了一条更便宜但
  更慢的站间路。这是「车级取优」的可见差异，不是缺陷。

## 3. M3 不可达处置（删桥边）

**为什么不用事件封路**：`closeRandomRoad` 显式跳过桥边（封闭后两端须仍连通），所以事件封路**永远**造不出不可达；必须用「手工增删…」删任意双向边。

**桥边实测（2026-11-24，4 对）**：`D04–T01`、`D16–T02`、`D23–T03`、`D24–T03`。

**CLI 复现（不依赖 GUI）**：

```bash
python3 - <<'PY'
lines = open('config/default.ini', encoding='utf-8').read().splitlines()
out = []
for ln in lines:
    p = [x.strip() for x in ln.split(',')]
    if len(p) >= 2 and {p[0], p[1]} == {'D04', 'T01'}:
        continue
    out.append(ln)
open('/tmp/no_bridge.ini', 'w', encoding='utf-8').write('\n'.join(out) + '\n')
PY
for s in distance time; do
  echo "==== $s"; ./build/app --config /tmp/no_bridge.ini --dump-plan $s 2>/dev/null | grep -E 'INFEASIBLE|PLAN'
done
```

**实测输出（2026-11-25，四车，工作区未提交修订）**：

```text
==== distance
PLAN V01 W01 W01 480
PLAN V02 - - 480
INFEASIBLE V02 无法从 W01 到达送达点: D04
PLAN V03 W01 W01 480
PLAN V04 W01 W01 480
==== time
（同上：V02 INFEASIBLE，原因逐字相同）
```

> **为什么是 V02 而不是旧版的 V03**：职责封闭（#46）后「簇 1 → V02、簇 2 → V03、簇 3 → V04」
> 是固定配对，D04 属簇 1，故由 V02 报不可达。数字变了是**结构变化**，不是回归。

**GUI 现场（8 步脚本的第 8 步，可选、放最后）**：

1. 重启进程（默认四车）。
2. 手工增删… → 选 D04 与 T01 → 删除边（双向）。
3. 重新规划 → 日志出现「不可达 / 不可行 + 原因」，且**照实拒绝并报原因**（不通过违反容量或先取后送去凑解）。
4. ⚠ 删边不可撤销；演示后重启进程。

## 规格八 #65 · 主场待命（2026-11-28 第八轮，工作区未提交修订）
