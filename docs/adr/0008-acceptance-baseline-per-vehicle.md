# 验收基线逐车冻结：车队级汇总对分配漂移失明，必须逐车钉住

**Status**: accepted（2026-11-23）

**Related**: wayfinder map #16 / issue #25（规格二 · 验收与演示口径）；上游 issue #19（异构车队：每车五项、完工耗时主口径）、[ADR 0003](0003-heterogeneous-fleet.md)、issue #30（三阶段分配：簇→车枚举 + 有界跨车改派）、[ADR 0005](0005-type-aware-allocation.md)、issue #28（跨车转运）、[ADR 0004](0004-transit-transfer-network.md)、issue #27（动态事件复调度）、[ADR 0007](0007-dynamic-event-rescheduling.md)、issue #29（指标与验收口径：13 字段 × 3 行、三层冻结）、[ADR 0006](0006-metric-definitions.md)。术语见 [`GLOSSARY.md`](../../GLOSSARY.md)。

## 背景与决定

规格二把车队从 1 台扩到 3 台（V01 快车 400kg/1.00/1.50，V02·V03 慢车 160kg/1.25/0.80）。#29 已定「三策略 × 13 字段」的车队级评审基线与三层冻结（L1 数值断言 / L2 文本守卫 / L3 oracle 算术对拍）。本票决定在这个基线上**再加一层**：

1. **每车 7 项 × 3 车 × 3 策略 = 63 个数也进冻结集**，与车队级 13×3 = 39 合计 **102 个常量**，同写 `tests/plan_golden.h`（单一真值表，L1 与 L2 共同 include）。
2. **每车路线节点序列逐字冻结**（`--plan-summary` 每车一行 `路线 V0x …`）。
3. 每车 7 项 = 距离 / 耗时 / 成本 / penalty / 载重利用率 / 取货准时率 / 送达准时率。**停靠数不进每车冻结集**——逐车路线序列已冻结，停靠数是它的函数；车队级停靠数由 13 字段第 5 项加 Σ 恒等式守住。

## 为什么（非显而易见的取舍）

### 车队级汇总对「哪台慢车跑哪个簇」完全失明

V02 与 V03 的 `capacity_kg / time_factor / cost_factor / start_node / depart_time` **五个参数全部相同**。因此把 V02 与 V03 的整条路线互换，车队级 13 个字段**一个都不变**。用 #30 表 2 的逐车实测数核对（三阶段解）：

| 策略 | 逐车（单数/停靠/距离/耗时/成本） | Σ停靠 | 完工耗时 | Σ距离 | Σ成本 | Σpenalty |
| --- | --- | --- | --- | --- | --- | --- |
| 距离 | V01 9/12/52.5/165/96.3；V02 7/8/29.0/93/28.1；V03 9/10/55.1/407/57.6 | 30 | 407 | 136.6 | 182.0 | 0 |
| 距离（V02↔V03 互换） | V01 9/12/52.5/165/96.3；V02 9/10/55.1/407/57.6；V03 7/8/29.0/93/28.1 | 30 | 407 | 136.6 | 182.0 | 0 |
| 成本 | V01 4/5/19.8/48/35.7；V02 12/16/75.9/233/75.7；V03 9/10/55.1/418/57.6 | 31 | 418 | 150.8 | 169.0 | 0 |
| 时间 | V01 9/13/69.8/378/137.1；V02 9/10/42.6/120/42.0；V03 7/9/61.8/181/63.4 | 32 | 378 | 174.2 | 242.5 | 0 |
| 时间（V02↔V03 互换） | V01 9/13/69.8/378/137.1；V02 7/9/61.8/181/63.4；V03 9/10/42.6/120/42.0 | 32 | 378 | 174.2 | 242.5 | 0 |

互换后完工耗时、Σ距离、Σ成本、Σpenalty、Σ停靠**逐项相同**。也就是说：**只看车队级 13 个字段，规格二最核心的新行为——「哪台车跑哪些单」——可以整条互换而测试全绿**。#30 的均衡度极差（0.54 / 0.85 / 0.76）也只能部分捕捉（V02 峰值利用率 1.00 与 V03 的 0.95 互换后极差仍是同一个数），且它按 #30 只作报告指标、不作硬约束。

结论：**车队级冻结守得住「总量没漂」，守不住「分配没漂」**。而分配正是 #30 的全部内容。

### 为什么不是「每车指标只打印、靠恒等式守」

恒等式（Σ每车距离 == 车队距离、完工耗时 == max(返回) − min(发车)、Σ每车耗时 == 车时合计）全部是**可加的对称量**：它们在 V02↔V03 互换下同样成立。恒等式只能抓住「实现把某台车的数算错」，抓不住「解本身变了」。要抓后者必须钉住**逐车**的具体数值与**逐车路线序列**。

### 为什么不做整行字符化

沿用 #29 §5.2 的裁定：整行字符化对任何标签/空格微调都红，失败信息只有「行不等」，诊断成本高；本项目历史上真正咬人的是**数值漂移**与**字段被静默删掉**两类。102 个常量（L1）+ 字段/格式/顺序守卫（L2）+ oracle 算术对拍（L3）三者分工不变，只是 L1 的覆盖面从 39 扩到 102。

## 关键约束

- **单一真值表**：102 个常量只写在 `tests/plan_golden.h`；`integration_tests` 与 `cli_plan_summary` 是消费方，不得各写一份。
- **两次捕获**：规格一（单车）落地后捕获一轮 13×3；规格二（三车）落地后重捕替换。schema 不变、数值变。
- **规格阶段不写死任何数字**：本票只定字段集合、冻结方式、落值位置与捕获流程。任何「新黄金值」在实施前都是编造。
- **容差沿用 #29**：距离/耗时/成本 0.001；百分数与在车量 0.1；penalty/停靠/动作整数。
- 每车指标与车队汇总必须可交叉核对（恒等式守卫），但恒等式**不替代**逐车冻结。

## 备选（已否决）

- **只冻车队级 13×3**（轻）：V02↔V03 互换全绿，分配漂移无声。已用上表否证。
- **每车只冻 5 项**（距离/耗时/成本/penalty/停靠数，45 个）：两率漂移仍可能漏，而两率是 #29 新增的三项指标之一。
- **每车冻 8 项含停靠数**（72 个）：停靠数已被冻结的路线序列完全决定，属重复真值。
- **每车指标只进 GUI、不进 CLI**：L2 文本守卫与 L3 oracle 对拍都拿不到每车数字，等于把新行为放进唯一没守卫的地方。
- **整行字符化**：见上「为什么不做整行字符化」。
