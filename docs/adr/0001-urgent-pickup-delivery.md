# 紧急订单改为客户间取送（A→B），中转站改为紧急降载暂存

**Status**: accepted（2026-10-30）

## 背景与决定

旧模型把紧急订单定义为「从**仓库**取货、直接送往某客户」，并为此配了一套 D23「满载出仓产生缓冲货 →
返程顺路寄存进站 → 紧急单用车上缓冲/站内库存就地满足」的机制。现按用户新需求**完全重构**为
**客户间取送**：用户 A 需把包裹送到用户 B，车辆先到 A 装、再到 B 卸，随后完成该紧急单。

据此决定：**彻底退役 D23 缓冲机制**（生产链 + 消费链 + 相关守卫/面板列），中转站的现行职责改为
**紧急订单的降载暂存点**——当车装着近满的普通货、装不下某紧急单包裹时，把部分普通订单货整单卸到
中转站腾出空间，紧急队列全部做完后再回站取回、继续普通配送。

## 为什么（非显而易见的取舍）

- **旧机制服务对象消失**：缓冲/就地满足的唯一用途是为"从仓库取货"的紧急单供料；包裹改从 A 来后，这条链无处可用。
- **中转站必须保留但只做降载**：D23 与 `docs/中转站策略分析.md` 已实测「常规趟经站二次配发整链更差」
  （距离 178.2→198.2km、趟数 6→13、penalty 256→323），所以**绝不恢复常规经站**；
  但新需求明确要"放中转站"，故中转站只在**紧急降载**这一处进站，并保证"总有位置"（容量无限）。
- 若不记录，后来者会以为"中转站只为紧急降载存在"是随手设计，甚至把它当 bug 去"修好"。

## 关键约束（实现与评审要守住）

- 优先级两档，**紧急 > 普通**；紧急队列**严格 FIFO**，新紧急单不凌驾执行中紧急单；紧急链（A→B）期间
  普通配送一律延后，唯 A、B 两点的**顺路交货**除外（且仅限**此刻已在车上**的普通货）。
- 降载按**整张普通订单**卸载；实践中任一时刻**至多一堆暂存货**（因普通单 20–42kg、紧急单 3–10kg，
  卸一单腾出的空间即足以容纳后续小紧急单）；若仍触发二次降载，也只并入同一站同一堆。
- **默认数据集无紧急单**，故三策略黄金值（178.2/378.3/244.2/166/6 等）应**逐位不变**；
  取送、降载、取回、顺路交货新增行为必须用新守卫 + 反向验证覆盖。

## 备选（已否决）

- **保留旧仓库取货语义**：与新需求冲突，否决。
- **保留 D23 缓冲链、另加取送**：两套站内库存并存，语义打架，否决。
- **常规趟经站二次配发**：实测更差（见上），否决；仅紧急降载例外。
