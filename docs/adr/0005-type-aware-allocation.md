# 类型感知的订单分配：整簇指派 + 全排列枚举 + 有界跨车改派

**Status**: accepted（2026-11-23）

**Related**: wayfinder map #16 / issue #30（规格二 · 类型感知的订单分配）；上游 [ADR 0002](0002-all-orders-pickup-delivery.md)（全订单 A→B 取送、停靠合并、逐单窗口 penalty）、[ADR 0003](0003-heterogeneous-fleet.md)（异构车队、每车一条连续路线、完工耗时为主口径）；[#18](https://github.com/Blorg51688/logistics-route-planner/issues/18)（单车构造器与决策键）、[#23](https://github.com/Blorg51688/logistics-route-planner/issues/23)（初始 25 单）、[#24](https://github.com/Blorg51688/logistics-route-planner/issues/24)（事件刷单）。术语见 [`GLOSSARY.md`](../../GLOSSARY.md)。

## 背景与决定

规格二的订单分配定稿为**三阶段**：

1. **阶段一 · 聚类**：簇 = 订单**取货点 A 的 `sub_network_id`**（复用已有数据字段，不引入新算法）。A、B 同子网络 = 本地单，进该簇；A、B 不同子网络 = **跨簇单**，不并入任何簇，单独成队列。手动「模拟新客户」单（B=新节点）按 A 的子网络归簇。
2. **阶段二 · 整簇指派**：簇数 ≤ 车数时，**枚举全部「簇→车」排列**（默认 3 簇 3 车 = 6 种），每种排列下各车独立跑 #18 的单车构造器（penalty 先 cheapest pair-insertion + EDD + 有界 relocate），按 #18 的字典序 `(Σpenalty, Σ策略权重, 均衡键, tieKey)` 取最优。
3. **阶段三 · 有界跨车改派**：以阶段二解为初解，做**单请求跨车 relocate**，R ≤ 3 轮，某轮无改进即停；**只动普通段**（紧急段由订单级 FIFO 完全固定，relocate 对其恒等）；接受条件 = 字典序**严格改进**，且**完工耗时不得变差**（见「为什么加完工耗时守卫」）。

**「类型感知」是枚举的结果，不是一张阈值规则表。** 跨簇单默认倾向快车、大簇/远簇在时间策略下自然落到快车——这些现象由枚举 + 字典序**产生**，不由手调阈值**规定**。

**载重均衡的度量**：逐车 **峰值在车 kg ÷ 该车容量**；车队「均衡度」= 各车该比值的**极差（max − min）**。地位 = 决策键第三级 + 报告指标，**不作硬约束**。

## 为什么（非显而易见的取舍）

- **为什么「类型倾向」不写成规则**：默认数据上**没有任何跨簇订单**（25 单 A、B 全部同子网络），单笔最大 **24kg**（远低于任何合理的「大宗」阈值）——**硬规则在默认数据上没有对象可作用**，写了也是空转；而三策略各自选出**不同**的簇→车排列（距离策略 簇1→V02，成本策略 簇1→V01，时间策略 簇3→V01），一套硬映射做不到「随策略分化」。全排列枚举**包含**了任何合理硬规则的全部可行解，硬规则只是它的一个子集。
- **为什么用 `sub_network_id` 而不是几何聚类**：数据里已有该字段（3 个子网络 9/7/9），复用即零新算法；手写 k-means/极角 sweep 会与既有字段打架（不一致时以谁为准），且几何聚类对时间窗是盲的（research §2.1(d) 的已知陷阱）。
- **为什么必须有阶段三**：纯两阶段在**车队主口径（完工耗时）上劣于基线**——距离策略 407min vs 顺序轮转 383min。原因是整簇不可分：sub3 整批压给一台慢车它 14:47 才回仓，而快车 09:32 就空下来了（92 / 196 / 407min）。阶段三把单笔订单挪到闲车上，是修这个边界的最小手段（research §3.3「cluster-first 只作初始解，配跨簇 relocate 修边界」）。
- **为什么加完工耗时守卫**：**无守卫的纯字典序 relocate 会退化**——时间策略下它把 22 单堆给一台慢车、快车只留 2 单（Σ时间权重 433.9 看起来更优，但完工耗时仍是 383、车队呈现极差），成本策略下完工耗时反而从 418 恶化到 429。守卫只有一条判定「本次改派不得让完工耗时变差」，属**一行代码级的机制**，却直接守住 #19 定为**主口径**的量——符合「呈现优先、拒复杂」。
- **为什么均衡用峰值利用率而不是「总 kg / 容量」**：**「总 kg ≤ 容量」是非法判据**——顺序轮转方案 V02/V03 各分到 165kg > 160kg 容量，但峰值只有 64 / 57kg，**完全可行**（容量约束在路线前缀上，ADR 0002 已定）。用总 kg 度量会把合法解误报为违规。峰值利用率与容量约束同源，不会被「>100% 却合法」误伤。
- **为什么均衡不作硬约束**：默认数据上整簇不可分时均衡极差最小就是 0.55，硬卡 0.3 会立刻不可行；唯一的出路是拆簇，而拆簇代价很大（sub1 整簇 39.8km，拆给两台慢车 60.8km，+53%），直接违背 ADR 0003 §9「一台车一个批次」的呈现。

## 备选（已否决）

- **显式类型规则**（跨簇/大宗/远距打标签后硬映射到车型）：默认数据上 0 条跨簇、0 条大宗 ⇒ 规则空转；且三策略共用一套映射，分不出差异。
- **几何聚类**（k-means / 极角 sweep）：与 `sub_network_id` 重复真值，且时间窗盲。
- **不加阶段三**（两阶段即定稿）：主口径劣于基线 24min，与 ADR 0003 把完工耗时定为主口径自相矛盾。
- **成对 relocate**（A、B 一起搬）：邻域大一倍，而单请求已把距离策略压到 136.6km（基线 213.2km 的 −36%），收益有限。
- **改决策键为先比完工耗时**：会推翻 #18 Q2=A 已定的 `(Σpenalty, 策略权重, tieKey)` 字典序；且轮转基线 383min 的低完工耗时是用 +69km 距离换来的。
- **均衡作硬约束**：默认数据立刻不可行，只能靠拆簇，代价 +53% 距离。
- **用「总 kg / 容量」度量均衡**：会把 165kg/160 这种合法解误判为违规。

## 关键约束

- **分配不变量**（验收直接断言）：① 全部订单被服务，每张恰好一台车、一次取货一次送达，不丢单不重复；② 簇归属完备且互斥，跨簇单不属任何簇；③ 每车路线**任一时刻** 0 ≤ 在车量 ≤ **该车** capacity（前缀峰值判定，**不得用总分配 kg**）；④ 每车从自己的 `start_node` 按自己的 `depart_time` 空载出发、回**同一**基地，空车返回时刻 = 发车时刻、五项全 0、不抬升完工耗时；⑤ 确定性：同输入必得同一分配，tieKey = (车辆 ID 升序, 节点 ID 升序, 订单 ID 升序)；⑥ 时间口径沿用 ADR 0003（用该车缩放后耗时重放，等待与 penalty 不乘因子，停靠零耗时，`arrival == we` 不算迟到）；⑦ 可加性：Σ每车距离/成本/penalty/停靠数 == 车队汇总，完工耗时与车时合计并列不互替。
- **兜底链**（某车装不下时按序退）：① 换车（枚举已覆盖全部排列）→ ② 拆簇（按 EDD 前缀拆成两段给两台车，仅此级触发并留日志）→ ③ 交 #18 的降载/全量兜底链 → 仍不可行则拒绝并报原因。
- **与 #27 的接口**：只交出**一个度量**——`边际代价(order, vehicle) → Δkey`，即用 #18 的 pair-insertion 评价器算「把该单插进去后的字典序 key 增量」。初始分配与动态插单**共用同一个度量**；#27 的「局部优先」= 只对「当前在车 + 当前位置之后的剩余段」重放它。本票**不定**「先试哪台车」的顺序。

## 已知代价（如实记录）

- **均衡度劣于基线**：峰值利用率极差——整簇分车 0.54（距离）/ 0.85（成本）/ 0.76（时间），顺序轮转基线 0.18 / 0.38 / 0.22。整簇不可分的结构性代价，**不掩饰**。
- **只有时间策略在主口径上占优**：距离策略 136.6km（基线 213.2，−36%）但完工 407min（基线 383）；成本策略 169.0 元（基线 310.8，−46%）但完工 418min；时间策略 378min **恰为可证下界**（D25 窗口 14:00 开 + 回程耗时 18.2min），优于基线 383min。
- **默认数据 0 条跨簇**：跨簇队列在默认数据上是空的，只在事件刷单（实算 69% 跨网）与手动新客户场景活起来。
