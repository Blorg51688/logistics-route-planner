# 指标口径：取货准时率用「不注定迟到」判据，载重利用率用时间加权在车均值

**Status**: accepted（2026-11-23）

**Related**: wayfinder map #16 / issue #29（规格一 · 指标与验收口径）；上游 issue #21（领域模型：A 无窗口）、[ADR 0002](0002-all-orders-pickup-delivery.md)（停靠合并/零耗时/硬优先）、issue #18（逐单 penalty）、issue #19（车队完工耗时、每车五项）、[ADR 0003](0003-heterogeneous-fleet.md)、issue #23（初始数据集与黄金值重算流程）、issue #24（事件模型：紧急单窗口 `[t, t+60]`）。术语见 [`GLOSSARY.md`](../../GLOSSARY.md)。

## 背景与决定

规格一新增三个指标（取货准时率、送达准时率、平均在车货量/载重利用率），并把摘要行的「趟数」换成「停靠点数 · 动作数」。三个指标的定义都有多个自洽的读法，本票定稿为：

1. **取货准时率 = 「不注定迟到」**：某单取货准时，当且仅当
   `取货到达时刻 + 该车 A→B 最短耗时 ≤ 该单送达窗口止`。
   含义是「货取到手之后，即使立刻直达客户也还赶得上」。
2. **送达准时率按单统计**，并**并列紧急 / 普通两个分项**；迟到判定逐单用该单自己的窗口止（`arrival == we` 不算迟到，沿用 #18）。
3. **平均在车货量 = 时间加权平均**：`Σ(每段在车量 × 该段耗时) / 总运行时长`；**载重利用率 = 该值 ÷ 该车 capacity**；多车按车时加权汇总，并**并列峰值**。

## 为什么（非显而易见的取舍）

### 为什么取货准时率不用「就绪时刻 + 宽限」，也不用 A 的窗口

领域模型（#21）已定 **取货点 A 无时间窗、不计 penalty**——所以「取货准时」没有天然截止时刻，必须人为指定基准。三条被否掉的路：

- **「就绪时刻 + 60min 宽限」**（票面提示的方向）：宽限是人造常数，且**指标值完全由这个常数决定**。按 #23 参考解实算（初始单就绪 = 08:00 发车时刻、宽限 60min）：sub1 枢纽取货 08:15 ⇒ 准时；sub2 枢纽 09:42、sub3 枢纽 11:11 ⇒ 均超限 ⇒ **9/25 = 36%**。也就是说「取货准时率 36%」说的是「我们把宽限定成了 60 分钟」，不是「路线取得不好」。
- **「取货到达 ≤ 该单窗口起」**：紧急单的窗口起**就是它的生成时刻**（#24 R4：紧急单 `[t, t+60]`），取货必然 ≥ 生成刻 ⇒ **紧急单恒为不准时**，指标在最重要的那一档直接失效。
- **撤掉该指标、改报「平均取货提前量」**：不引入阈值，但与已拍板的「新增取货准时率」字面不符。

选定的「不注定迟到」判据**不需要任何人造常数**：它的两个量（取货到达时刻、该车 A→B 最短耗时）都来自配置与规划结果，其中 A→B 最短耗时按该车缩放后的耗时取（#19：`timeEff = edge.timeMin × time_factor`；标量缩放下 argmin 不变，故等于基础最短路耗时 × `time_factor`）。它回答的是一个有业务含义的问题：**这张单在取到货的那一刻还有没有机会准时送达**。与送达准时率互补——取货侧是「还有没有机会」，送达侧是「实际结果」。

### 为什么送达准时率按单而不按停靠

#18 已定**逐单窗口 + penalty 逐单累加**（停靠不再有合并窗口）。按停靠统计会掩盖「合并停靠里一单迟到、一单准时」这种正是逐单口径要修掉的情形。紧急 / 普通分列的理由：硬优先模型下紧急单迟到比普通单迟到严重，合成一个百分数会被普通单稀释。

### 为什么平均在车量用时间加权，而不是逐停靠平均

逐停靠平均（`Σ离开停靠时的在车量 / 停靠数`）**完全不含行驶时长权重**：在枢纽装满 160kg 只停一瞬、与满载跑 60 分钟，在这个口径下贡献相同。时间加权平均才是「载重利用率」的标准含义，并且**能反映空驶**——车辆跑长空腿时利用率被拉低，而这正是异构调度（规格二）要优化的东西。峰值保留并列显示：它是既有演示点（#23 参考解 196/200），且能一眼看出容量是否真的咬合。

分母固定用**该车 capacity**：不用「额定载荷」（同义反复），也不用「总需求」（随数据集变，跨策略不可比）。

### 为什么「趟数」换成「停靠点数 · 动作数」，而不是「取送对数」

要回答的是「实际访问了多少次、一共做了多少事」。**取送对数 = 订单数**，它与基准数据上的停靠点数恰好都等于 25（#23：A 集合 6 个节点、B 覆盖全部 25 个配送点、A∪B = 25 个节点）——并列打印两个相同的数字，读者会问「为什么给两遍」，而且它不携带「合并」这个信息。

**动作数 = 取货动作数 + 送达动作数**（每单恰一次取货、一次送达）。它与停靠点数构成比值 `停靠 / 动作`，这才是合并的效果：**若完全不合并，50 个动作需要 50 次访问，比值 = 1.0；基准数据是 25 次访问承载 50 个动作，比值 = 0.5，即合并把访问次数砍了一半**。这个比值越小，合并越多。

需要如实记录两点：

- 动作数恒等于 **2 × 订单数**（结构性恒等式，不是独立可观测量）。它真正提供的信息在**与停靠点数的比值**上，所以摘要行必须两个数一起给，单独给动作数没有意义。
- 刷单后两者会进一步分开：订单增多、但新单的 B 常常落在既有停靠点上 ⇒ 停靠点数增长慢于动作数 ⇒ 比值进一步下降。「取送对数」作为**报告用口径**保留（它直白表达「服务了多少张单」），只是不进摘要行。

## 关键约束

- 取货准时率的判定**只看取货那一刻**，不随后续路线变化回溯；它不替代送达 penalty。
- 送达准时率的分母 = 已规划订单数；紧急分项分母 = 紧急订单数，**分母为 0 时显示「—」**，不显示 0% 或 100%。
- 平均在车量的时间区间覆盖**整车运行时长**（发车到返回基地），含基地往返的空载段——空驶计入分母、不计入分子，这正是它能反映空驶的原因。
- 降载 / 暂存场景下，卸到中转站的货**不算在车**；取回后重新计入。在车量始终是「车上实际货量」。
- 三项指标都是**确定性的规划结果**，可进黄金值；但具体数值必须在实施落地后由 `--plan-summary` 捕获，**规格阶段不写死**。

## 备选（已否决）

- 取货准时率 = 就绪时刻 + 60min 宽限（指标被常数决定，基准数据上 36%）。
- 取货准时率 = 取货到达 ≤ B 窗口起（紧急单恒不准时）。
- 撤掉取货准时率，改报平均取货提前量（与已拍板票面不符）。
- 送达准时率按停靠统计（与逐单 penalty 口径不一致）。
- 送达准时率只给总数、不分紧急/普通（紧急迟到被稀释）。
- 平均在车量 = 逐停靠平均（不含时长权重，无法反映空驶）。
- 载重利用率分母用总需求或额定载荷（随数据集变 / 同义反复）。
- 摘要行给「取送对数」（基准数据上与停靠点数同为 25，两数相同、且不携带合并信息）。
