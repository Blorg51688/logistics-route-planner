# 跨车转运网络：整单在站转货、drop-and-go、严格更优才启用

**Status**: accepted（2026-11-23）

**Related**: wayfinder map #16 / issue #28（规格二 · 中转转运网络）；前序 [ADR 0002](0002-all-orders-pickup-delivery.md)（中转站只存车辆实际卸下的货）、[ADR 0003](0003-heterogeneous-fleet.md)（本决定**精确化**其不变量 4「一单由一台车全程完成」）。术语见 [GLOSSARY.md](../../GLOSSARY.md)。

## 背景与决定

规格二已拍板「转运枢纽＋绝不更差」（P2Q4=A）与「站账守恒、容量不限」（P2Q5=A）。本票（#28）定稿机制本体，本人 2026-11-23 拍板六个分叉：

1. **Q1=A drop-and-go**：卸货车即卸即走，唯一约束是时刻链「取货 ≤ 卸入 ≤ 取走 ≤ 送达」；不引入两车会合窗。
2. **Q2=A 整单不可拆**：一张订单任一时刻只在一处（某车车上，或某站站内）；转运 = **整单卸、整单取**；penalty 由最终送达的那台车记一次。
3. **Q3=C 紧急单只作最后手段**：仅当禁转运版给该紧急单记了 penalty 才试转运，且必须**严格降低该单的 penalty**；FIFO 精确化为「U_k 的送达**时刻** ≤ U_{k+1} 的取货**时刻**」，「同刻至多一张紧急单在车」精确化为「…处于**已取未送**（在车**或**在站）」。
4. **Q4=A 严格字典序更优才启用**：key = (Σpenalty, 当前策略权重合计, tieKey)；**完全并列 ⇒ 保留禁转运版**；penalty 一票否决＝字典序第一键。
5. **Q5=A 场景门控**：只在跨簇订单 / 容量腾挪 / 紧急响应三条可执行判据之一成立时构造转运候选。
6. **Q6=A 站内等待 ≤ 60min**（代码常量，不加配置键），超限该转运候选不可行。

## 为什么（非显而易见的取舍）

- **为什么 drop-and-go 而不是 rendezvous**：本项目已把「停靠零耗时」定为铁律（ADR 0002 Q3），站在模型里就是一个无成本的货架；再引入两车会合窗，等于给一个本来免费的东西加同步成本，还要把**两条路线**的时刻表耦合推进。收益（限制站内等待）用 Q6 的一个常量就能拿到。
- **为什么整单不可拆**：拆单会让一张单出现**两个送达停靠** ⇒ 逐单窗口 penalty 必须重新定义（记两次＝重复罚，记最后一次＝掩盖前一批迟到），custody 也要按批次记。默认单 19–24 kg、慢车 160 kg，整单腾一张已能让出 12–15% 容量；收益弱而代价是两个基础不变量重写。
- **为什么紧急单只作最后手段**：紧急单是可观测收益最大的一类（`docs/中转站策略分析.md` §四实测 100 min 差），但也最容易被三条冻结不变量挡住。把触发压到「直达版已记 penalty」⇒ 只在有 penalty 可救时动用，且必须严格降低，天然满足「绝不更差」。
- **为什么必须「严格更优」而不是「不更差」**：本图 84.2% 的配送点对存在**精确零绕行**站，加上停靠零耗时 ⇒ 转运的距离/耗时/成本增量恒为 0 的情形占绝大多数。弱判据会把大量零收益转运放进来：路线、custody、停靠数全变而三项指标不动，验收成本陡增。严格更优使「完全并列 ⇒ 保留禁转运版」成为一句可执行的话。
- **为什么场景门控而不是全枚举**：默认数据 505/600 点对都有零绕行站；全枚举是 O(m²k) 次构造 × O(m·n³)，远超 #18 已接受的规模。三条判据正好对应票面的三个启用场景，每条一行条件、可单独验收。

## 备选（已否决）

- **rendezvous / 计划时刻表（半同步）**：新增同步窗参数、耦合两条路线时刻推进、在 3 车 25 单规模下剪死大量候选。
- **允许拆单 / 只在站内拆**：penalty 口径与 custody 两个基础不变量重写，收益弱。
- **紧急单常态参与转运**：三条紧急不变量全面改写，且没有「必须更好」的门槛。
- **「不更差」即启用 / 只比 penalty**：前者放进大量零收益转运，后者废掉 #18 的字典序第二键。
- **全枚举候选 / 不做门控**：候选爆炸。
- **站内等待不设限**：转运可把等待搬进站里刷指标，而摘要在表面一切正常。

## 关键约束（实现与评审要守住）

- **接收车必须 ≠ 卸货车**：同一台车卸了再取回是 #18 的**降载暂存**，不是转运。两者共用「站」与「只存车辆实际卸下的货」的语义，但**分开写、分开验收**。
- **时刻链**：取货(A) ≤ 卸入站 ≤ 取走站 ≤ 送达(B)；站内等待 = 取走 − 卸入 ≤ 60 min。
- **守恒**：任一站任一单，站内量 ∈ {0, kg}；Σ卸入 − Σ取走 ≥ 0；**计划期末恒为 0**（不存在「留站过夜」的合法计划）。
- **账本可追溯**：每笔记 (orderId, stationId, kg, inVehicleId, inTimeMin, outVehicleId, outTimeMin)，卸入与取走**两端都必填**。
- **penalty 归属**：最终送达的那台车记一次；取货车不记。
- **每车指标**：距离/耗时/成本按各自实际跑的那一段记；站停靠计入该车停靠数（文本口径归 #29）。
- **跨重规划**：站内存货只能来自**已实际执行的卸入**；计划内尚未执行的卸入在重规划时全部作废（不得跨轮累积——P25 的 `stationStock_` 正是「库存单调膨胀 870 kg」的载体）。
- **验收读规划产物**：账本逐笔可核、期末 0、时刻链、容量前缀、penalty 归属；反向验证（回退修复必须失败）。

## 已记录的历史偏离（如实）

- 票面的「紧急响应」场景在 Q3=C 下被**收窄**为「只救 penalty」，不是常态启用。
- 票面写「任意车可顺路取走并送达」；本票落实为「接收车由候选枚举 + 严格更优判据共同决定」——**不保证**「顺路」总是成立，不成立时判据会否决它。
