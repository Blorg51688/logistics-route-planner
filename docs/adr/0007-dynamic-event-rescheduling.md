# 动态事件复调度：单一车队时钟、局部优先五级升级链、逐车紧急 FIFO

**Status**: accepted（2026-11-23）

**Related**: wayfinder map #16 / issue #27（规格二 · 动态事件复调度）；上游 issue #24（事件模型与 D24 软件内时间结算）、issue #18（单车构造与 §10 重规划链）、issue #19（异构车队、§5「同刻至多一张紧急单在车」按车计）、[ADR 0003](0003-heterogeneous-fleet.md)、issue #28（转运网络、§6.3 已执行卸入继承、§8.1 降载与转运并列比较）、[ADR 0004](0004-transit-transfer-network.md)、issue #30（三阶段分配、边际代价 Δkey）、[ADR 0005](0005-type-aware-allocation.md)、issue #29（指标口径）。术语见 [`GLOSSARY.md`](../../GLOSSARY.md)。

## 背景与决定

规格一把「事件结算挂在软件时间前进上」（D24）定在**单车**上：一个 `state_.atTimeMin`、一个 `nodeIndex_`、一个 `nextEventMark_`。规格二把车队扩到 3 台后，「推进一站」「推进一刻」这两个动作必须先回答「推进谁」，否则 D24 §7.5 的等价性判据无从谈起。本票在五个地方做了不可逆的取舍：

1. **单一全局车队时钟 + 一个推进原语**。定义 `advanceFleetTo(T)`：把每台车的游标各自推进到「下一个节点到达时刻 > T」，然后 `settleEventsUpTo(T)`。于是「推进一站」= T 取**所有车下一个节点到达时刻的最小值**；「推进一刻」= T = `nextEventMark_`。**等价性由构造保证**，不靠断言兜。
2. **局部优先的五级升级链**：局部重排 → 跨车再分配 → 全车队重调度 → 降载/转运并列比较 → 拒绝并报原因。**「失败」= 该级产不出可行解**（容量 / 窗口 / 可达 / 先取后送任一违反）。
3. **局部可行即接受，不做「局部 vs 全局两版取优」**。「两版取优」只保留在 #28 已定的两处（转运版 vs 禁转运版、降载 vs 转运）。
4. **紧急 FIFO 逐车**：每台车各自「全部紧急停靠先于全部普通停靠」+「**车内**订单级 FIFO」；**显式放弃**「全车队同刻至多一张紧急单在执行」的读法。
5. **不重写 A→B 版的 leg 级增量重规划**，改用「顺序不变版 vs 重排版」两版比较。这是对 #18 §10 的**显式偏离**。

## 为什么（非显而易见的取舍）

### 为什么时钟必须全局唯一

D24 §7.7 已经给出过这条纪律的单车版本：事件由**软件内时钟**决定，不由「按了哪个按钮」决定；只要有一条推进路径不结算事件，两条路径就会抽到不同次数的事件、走不同的重规划，等价性必然失败。多车把这个问题放大：若每台车各有一条时钟，「两台车先后跨过同一个事件刻」就产生了「结算一次还是两次」的新歧义，而这个歧义没有任何天然答案——只能靠额外状态机压住，或者靠断言事后比对。

单一全局时钟把歧义**消除**而不是压住：事件刻属于车队，不属于某台车；两条推进路径都归结为「把车队时钟推到 T，把每台车推到 T，再结算」。守卫于是从「证明两套逻辑一致」退化成「证明一个原语被两条路径共用」——这是本项目一贯的做法（`onAdvanceStop` 是唯一状态转移点，见 `MainWindow.h` 的 VehicleState 注释块）。

代价如实记录：「推进一站」的语义从「这台车走一站」变成「全局走一站」，最慢的那台车决定节奏。

### 为什么紧急 FIFO 必须逐车

本图实算：配送点之间的**时间直径只有 31.1 min**（D18→D06），而紧急单窗口是 **60 min**（#24 R4）。4000 例随机 A≠B 紧急单里，三台车从各自枢纽空载出发**全部**能在 60 min 内送达 ⇒ 三车的 `Δpenalty` 恒为 0，跨车再分配的收益**只可能来自并行**，不可能来自「换一台更近的车」。

于是全局 FIFO 会把唯一的收益通道堵死：紧急单 U1 在 t−15 刻派出、执行约 40 min；U2 在 t 刻到达。全局 FIFO 下 U2 必须等 U1 在 t+25 送完再花 40 min ⇒ **t+65 送达，超窗 5 min**；逐车 FIFO 下 U2 直接派给另一台车 ⇒ **t+40 送达，penalty 0**。这不是理论推演，是用本图的最短路表算出来的。

「全局至多一张紧急单在执行」这条读法并非无源：它来自 #21「紧急硬优先」在单车时代的自然形态。但 #19 §5 已经把它落成「**按车计**」，#28 §9.3 又把它精确化为「同刻至多一张紧急单处于**已取未送**（在车或在站）」——后者要防的是「同一张单被记成两张」，不是「两台车各有一张」。本票把这两句话的边界写死：**逐车成立；跨车并行是允许的**。

代价如实记录：一场 25 刻的模拟里，约 0.9 个刻会出现「两张紧急单分属两台车、同时在执行」（0.075/刻 × 约 4 刻占用 ⇒ λ≈0.30，泊松近似下 P(≥2)≈3.7%/刻）。演示时需要能解释这件事，不能让人误以为 FIFO 失效了。

### 为什么不重写 leg 级增量，改用两版比较

#18 §10 的重规划链是「先 leg 级增量（D22，停靠顺序不变）→ 仍不可行则全量兜底」。这条链在 A→B 模型下**目前没有实现载体**：`src/core/RoutePlanner.cpp` 的 `replanIncremental` 对「剩余订单里任一 `pickupNodeId` 非空」直接 `return replan(...)`——而新模型下**所有**订单都有取货点 A。MC-A10 已把这条登记为「当前代码里已经在退化、但没有任何守卫能看见」的一项。

重写 A→B 版 leg 增量要处理「A 落在 leg 内 / B 落在 leg 内 / A、B 跨 leg」三种情形并各配守卫，正好是历史上反复出缺陷的那类形状（P25/P28：从计划反推物理事实）。而它要换来的东西——「路况只改一条边时路线逐字不动」——用**纯重放**就能拿到：停靠顺序不变、只把新边权重重放一遍得到新时刻/等待/penalty/策略权重。

所以本票把这一层换成两版比较：**顺序不变版**（重放）与**重排版**（对该车剩余订单重跑 pair-insertion + repair R≤3），**严格更优才改序**。这不是「用复杂代替真实」，而是**删掉一个已经死了的机制、换一个语义等价且能守住的机制**。偏离已如实登记，交接 #26 成稿与 #20 清单。

### 为什么局部可行就不再跑全局

P2Q6=A 的定稿就是「局部优先 + 升级兜底」。把它执行到底意味着：局部能解就不跑全局。实算支撑：一场 25 刻的模拟里路况事件约 16.9 次，每次改动 11 条边、其中期望 5.5 条转拥堵；逐车命中概率 54%/51%/54%，**平均命中 1.60 台车**、三台全中占 15%。若每次命中都跑一遍全车队重调度（6 种簇排列 × 3 簇构造 + relocate R≤3），用户看到的会是一张不停跳动的图。这与 #18 Q4=B「不做周期性全量重规划」是同一个判断。

代价如实记录：短视，可能错过「全局更优」的解。这是被显式接受的。

### 为什么先降载后转运、并列保留降载

#28 §7.3 已经用同一个理由定过「完全并列保留禁转运版」：本图 84.2% 的配送点对存在**精确零绕行**站，加上停靠零耗时 ⇒ 转运版在 distance/time/cost 上**常常完全并列**。若并列时选转运，默认数据会被大量零收益转运改写。

降载与转运的并列遵循同一条：**降载是同车、不依赖另一台车的路线，是更小的改动**；并列时选改动小的那个。执行顺序固定为「先构造降载版、再构造转运版」——顺序固定才能保证确定性（同输入必得同一 plan，#19 不变量 9）。

## 关键约束

- **事件刻属于车队**：一个全局 `nextEventMark_`；每刻恰抽 1 个事件、恰消耗 1 次抽签（#24 §3 不变）。
- **推进原语唯一**：`advanceFleetTo(T)` 是唯一把「软件内时间」变成「车辆状态转移」的入口；两条推进路径都必须经过它。
- **已执行前缀不可重排**：在车货、站内已执行账本、各车当前位置与时刻，一律作为复调度的**输入常量**（与 #18 §10「兜底范围」同口径）。
- **账本分两类、继承规则不同**：降载暂存（同车）沿用 #18 Q10=A 由原车取回；转运账本（跨车）任一可行车取走，且期末必须为 0（#28 §6.1 C3）。**未执行的卸入不需要清理动作**——复调度的输入里根本没有它，随旧计划一起丢弃。
- **局部重规划只作用于「受影响车」的集合**：路况按逐车 `needsReplan`（增幅达标 **且** 该边在该车剩余路线上）判定；封路按「该车剩余路线是否用到被封闭边」判定。集合可以是 0 台（10.2%）、1 台（34.9%）、2 台（39.8%）、3 台（15.1%）——**不能写成「最多一台车」**。
- **待处理上限仍是全局的**：紧急 2 / 普通 6 计的是**订单数**（#24 Q4=A），与车队规模无关；满额仍在抽签前置 0 权重。
- **指标一律按 #29 在复调度后重算**，不在本票另立口径。

## 备选（已否决）

- **每车一条独立时钟**，事件按「任一车跨过事件刻」结算（要额外定义「同刻只结算一次」，把构造保证换成断言）。
- **只在「推进一刻」结算事件**（直接违反 D24 §7.7，等价性断言必然失败）。
- **重写 A→B 版 leg 级增量作为第一层**（三情形 × 三守卫，正是 MC-A10 判定的退化点）。
- **只重放、永不重排**（封路导致 leg 不可达时无法局部修，只能升级；路况变慢时无法靠换序消化）。
- **每次事件都跑全局 + 两版取优**（路线抖动，且等于推翻 #18 Q4=B）。
- **周期性跑全局**（#18 Q4=B 明确否决）。
- **全局 FIFO：全车队同刻至多一张紧急单在执行**（唯一收益通道被堵死，算例 penalty 5 → 0 变成 5 → 5）。
- **只试 Δkey 最小的车**（明明第二台车能装下的单会掀翻全车队重排）。
- **按车辆 ID 顺序试车**（放弃 #30 交出的唯一度量）。
- **已执行卸入一律由原卸入车取回**（退化成降载，且原车可能已走远或已满载）。
- **固定由原计划指定的取走车完成**（复调度经常失败，退回也未必可行）。
- **先转运后降载、并列保留转运版**（并列时选跨车耦合更深的方案）。
- **等价性守卫只断言事件日志、不断言终态**（路线/账本偏差看不见，正是 P25/P28 那类缺陷）。
- **用 `nodeIndexAtTime` 直接比对下标**（它是显示用函数，拿它断言等于「从计划反推物理事实」）。
