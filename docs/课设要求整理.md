## 1. 课程设计目的

- 是将理论与实际联系的必要过程，是【数据结构】教学的重要环节。
- 加深对课程内容的理解，掌握各种数据结构的应用方式。
- 提高软件设计与制作能力，为培养具有良好程序设计素质的计算机人才打下基础。

## 2. 课程设计方式与阶段

- 教师给出规范题目需求，学生**独立完成**相应题目，由教师**分阶段检查 + 最后验收**。
- 四个阶段：
  1. **第一阶段**：公布题目及要求（开学第 1 周，在「日新学堂」发布）。
  2. **第二阶段**：按题目要求独立完成。
  3. **第三阶段**：撰写课程设计报告。
  4. **第四阶段**：第 15、16 周检查验收。
- 学生应遵循的过程：**分析 → 设计 → 编码 → 调试并测试**。
  - 分析：理解基本需求与功能，明确输入数据、输出结果与形式，抽取数学模型，选择数据结构。
  - 设计：确定存储结构，设计模块及其关系、各操作算法与用户界面。
  - 编码：使用**面向对象语言**实现；**不能使用类库、模板等（用户界面除外）**。
  - 调试测试：选用适当测试数据，尽量覆盖各种情况；各阶段生成对应报告文档。

## 3. 课程设计要求（纪律与评分）

1. 每位学生**独立完成**分配到的题目（同学间可商量，**严禁抄袭**）。

## 5. 第 2 题：电商物流配送路径规划系统

### 5.1 问题描述

模拟城市物流配送场景，用**图数据结构**构建配送网络模型，支持订单分配、多目标路径优化及实时调度，解决「最短路径规划」「动态订单响应」等实际问题。

配送网络核心元素：

1. **节点**：物流网络关键地点，包括
   - **仓库（起点）**：货物初始位置，每个配送任务从仓库出发；
   - **配送点（客户）**：接收货物目标位置，需满足**时间窗口**（如 9:00–11:00 送达）和**货物需求量**；
   - **中转站**：临时存储/中转（如偏远区域集散点），**可嵌套子配送网络**（如「中转站 A 下属 3 个社区配送点」）。
2. **边（路径）**：连接节点的**有向带权边**，表示实际道路，权重包括：
   - **距离（公里）**、**预计耗时（分钟）**、**运输成本（元）**。

### 5.2 基本要求

系统需根据**订单需求**（配送点、货物量、时间窗口）和**车辆信息**（载重等），自动生成最优配送路径，并支持配送过程中响应新订单。

1. **图数据结构设计**
   - 有向带权图：顶点 = 节点（仓库/配送点/中转站，含唯一 ID）；边 = 路径（含距离、耗时、成本属性）。
   - 网络规模：**节点总数 ≥ 30**（含**至少 2 个仓库、15 个配送点、3 个中转站**）；**路径总数 ≥ 50**。
   - 支持**动态添加/删除节点和边**（模拟新客户或道路封闭）。
2. **配置与初始化**
   - 通过**配置文件**定义基础参数：节点坐标 (x, y) 及类型、路径权重初始值、车辆参数（载重上限）、订单列表（配送点 ID、货物量、时间窗口）。
3. **核心功能**
   - 输出图的**邻接表 / 邻接矩阵**表示，并**可视化配送网络**（图形界面展示节点位置、路径方向及权重标签）。
   - 实现**单车辆基础路径规划**：从仓库出发，遍历所有待配送点后返回仓库，支持两种策略：
     - **最短距离路径**（基于 Dijkstra 算法）；
     - **最低成本路径**（基于边的成本权重）。

### 5.3 扩展要求

1. **支持配送过程中响应路况变化**
   - 当某路径因拥堵导致耗时增加 **20% 以上**时，系统**自动触发路径重新规划**，并在界面中**更新路径高亮**。
   - 实时路况为动态属性，如「拥堵」「畅通」。
2. **复杂约束处理**
   - 加入**时间窗口硬约束**：若配送点超出规定时间送达，标记为「超时订单」并记录 penalty。
   - 支持**动态订单插入**：配送过程中新增紧急订单（如「1 小时内送达」），系统需调整现有路径，优先满足紧急订单。

### 5.4 实现提示

1. **图存储与遍历**
   - 采用**邻接表**存储图（适合稀疏路径网络）；每个节点对象包含：ID、类型、坐标、邻接边列表（边对象含目标节点 ID、权重属性）。
   - 路径搜索算法：基础功能用 **Dijkstra**（单源最短路径）。
2. **算法优化**
   - 实时路况更新：用**随机数**模拟路况变化（如每 30 秒修改 10% 路径的耗时权重）；触发路径重规划时采用**增量式更新**（仅调整受影响的路径段）。

## 6. 课程设计报告要求

### 6.1 报告内容结构（至少包含下列部分）

- **【需求分析】**
  1. 程序需要完成的功能（题目明确要求的功能 + 为构建程序必须添加的管理功能）；
  2. 需要处理的数据；
  3. 程序开发运行选用的环境；
  4. 用户界面的设计等。
  - 要求用简练、清晰的语言与图表把需求描述清楚。
- **【数据结构设计】**
  1. 所定义的主要数据结构；
  2. 程序整体结构以及各模块的功能描述。
- **【详细设计】**
  - 主要函数的**流程图**和局部的数据结构说明等。
- **【测试】**
  - 给出整个程序的测试用例与测试结果。测试用例须包括：**正确运行程序的用例**、**导致程序运行错误的用例**、**边界数据的用例**等。
- **【总结与提高】**
  - 个性化总结：开发中的体会与收获、遇到的问题与解决情况、对完成课设情况的自我评价等。

## 7. 关键约束速查（开发时须遵守）

- ✅ 用**面向对象语言**实现。
- ❌ **不能使用类库、模板等**（**用户界面除外**）—— 图、堆、队列等数据结构需自行实现。
- ✅ 需求中指定用 **Dijkstra**、**邻接表**存储。
- ✅ 需要**配置文件**驱动初始化；需要**图形界面**可视化网络与路径高亮。
- ✅ 需支持**动态增删节点/边**、**路况变化重规划**、**时间窗口硬约束 + 超时 penalty**、**动态订单插入**。
- ⚠️ 验收会**现场改需求并现场改代码** —— 设计上需留出可扩展性（但注意第 1 名 rung：不要过度设计）。
- 📌 建议全程用 **Git** 提交（有加分），保持有意义的 commit 历史。

## 8. 已确定的项目决策

| 项 | 决策 | 说明 |
| --- | --- | --- |
| 选题 | **第 2 题 电商物流配送路径规划系统** | 工作区仅含第 2 题文件 |
| 语言 | **C++** | 面向对象，符合要求 |
| GUI | **Qt（Qt Widgets）** | UI 属「不能用类库」的豁免范围 |
| 核心算法口径 | **Dijkstra 逐点最短路累加** | 单源最短路求各配送点间最短路径，再用贪心顺序串联成配送路线；不实现全局 TSP |

### 架构原则（由约束推导）

- **核心层纯 C++，零第三方依赖**：图、邻接表、优先队列/堆、路径算法等全部手写，可直接用 `g++` 编译并跑最小测试，满足「不能用类库/模板」与可测试性。
- **Qt 只做薄薄的 GUI 展示层**：读取核心层输出的图与路径结果做绘制，不承载业务算法。

## 9. 待与指导教师 / 需求方澄清的开放问题

1. ~~**实现语言与 GUI 技术栈**~~ → **已定：C++ / Qt**（见 §8）。

5. ~~**「最优」目标口径**~~ → **已定：Dijkstra 逐点最短路累加**（见 §8）。
6. **配置文件格式**：JSON / CSV / 自定义文本 / INI？
7. **中转站嵌套子网络**：是否需要显式建模「中转站下属子配送网络」的层级结构（多级图），还是扁平图即可满足？
8. **可视化权重标签**：三条权重（距离/耗时/成本）在界面上如何显示与切换？
