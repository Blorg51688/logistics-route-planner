# 电商物流配送路径规划系统

> **数据结构课程设计 · 第 2 题**（北京工业大学，2026-2027 学年第 1 学期）。
> 用**有向带权图**（邻接表存储）建模城市物流配送网络；手写二叉堆与 Dijkstra 求最短路径；
> Qt6 图形界面可视化网络与路线；支持时间窗口硬约束、载重分批、路况变化重规划与紧急订单插入。

---

## 环境要求

| 依赖 | 用途 | 缺失后果 |
|---|---|---|
| `cmake` ≥ 3.20、`g++`（支持 C++17） | 构建 | 入口脚本会明确报出缺哪个 |
| Qt6 Widgets 开发包（`qt6-base-devel`） | 图形界面 | 核心逻辑与测试照常可跑，但**主界面程序不会生成**（入口脚本会提示怎么装） |
| 图形显示（`DISPLAY` 或 `WAYLAND_DISPLAY`） | 弹出窗口 | 入口脚本会改为提示命令行/离屏渲染的替代查看方式 |

> 「不能用类库、模板」是课程硬约束，落地口径是：**课程考点的「算法主体」必须手写**——
> 邻接表、二叉堆、Dijkstra、贪心串联的逻辑全部自己写，不用 `std::sort` 代替排序、
> 不用 `std::priority_queue` 代替手写堆。
> 除此之外**不受限**：`std::vector` / `std::map` 等容器、`std::min` / `std::max` /
> 迭代器、以及所有辅助功能都可以随意用 STL（完整边界见 `docs/设计.md` §10.1）。
> Qt 只用在界面层（属要求中「用户界面除外」的豁免范围）。

## 快速开始

```bash
# 1) 启动主软件（首次会自动构建）
bash start-here/run/启动软件.sh

# 2) 人工测试向导（8 关，约 5–6 分钟；它自己也会确保已构建）
bash start-here/run/人工测试向导.sh
```

> 命令等价于直接在项目根运行根目录的 `启动软件.sh` / `start-here/run/` 下的 `人工测试向导.sh`——`start-here/run/` 是快捷入口，实现只有一份。

## 附：其他常用命令

入口表只列了三条最常用的路。下面是**同一套东西的命令行形态**，适合写脚本或快速自查
（都需要先构建一次，`bash 启动软件.sh` 会顺手做掉）：

**先构建一次**（`bash 启动软件.sh` 会顺手做掉），然后：

```bash
(cd build && ctest)                      # 跑全部自动化测试（20 个目标 / 829 项断言）
```

主程序的各种用法（在**工作区根目录**执行）：

```bash
./build/app --help                       # 主程序全部命令行选项
./build/app --plan-summary distance      # 三种规划策略的汇总（distance / time / cost）
./build/app --dump-graph list            # 邻接表（--dump-graph matrix 是邻接矩阵）
./build/app --self-check-actions         # 插单不丢单等交互性自检
./build/app --ui-probe                   # 断言工具栏与侧栏确实构造完整
QT_QPA_PLATFORM=offscreen \
  ./build/app --render-window /tmp/gui.png   # 无显示环境下把完整窗口渲染成图片
```
